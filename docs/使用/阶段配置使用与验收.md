# 阶段配置：使用与验收

更新：2026-09-28。投资规则以[仓位与再平衡规则](../体系/仓位与再平衡规则.md)为准。

## 仍使用原来的三个入口

1. **概览**：查看方向市值、当前占比和阶段目标。券商直接现金归现金，两个投顾作为待迁移余额，赎回在途单列。缺失账户不会自动按零填补。
2. **账户**：沿用原有六个账户入口，其中平安为新增。平安填写实际可用/冻结现金与持仓；纳指执行代码、限价及其基准日、最小交易单位、佣金小数费率和最低费用在两个方向的交易条件中维护。501312固定归其独立方向。仅保存核实过的事实，不用研究报价代填。
3. **计划**：生成完整计划。按一个阶段目标来源生成预算、银证调拨和账户内订单。资金前提与不可执行原因直接展示；基金使用核实限价和费用换算整手，股票/转债继续由原策略生成订单。

账户记录为六个：广发、华泰、平安、资金账户、国内长钱、海外长钱。平安空仓也须通过账户页明确记录空仓及真实现金，不等同于系统从缺失推定为零。

## 常见情况

- 新钱：只增加资金池余额，下一次计划统一计算，不填写另一套月度分配表。
- 投顾赎回：持有余额减少、在途增加；到账后在途减少、资金池增加。一次资产只占一个位置。
- 基金条件不足：该方向目标仍在，计划明确缺项；不会自动改买另一只基金。
- 银证转入：订单预算带有到账前提，实际未到款不能下单。券商回池还须检查可取状态。
- 旧计划：旧配置或输入变更后仅供历史查询，不能继续执行。一次操作后按新账户事实重算。
- 原策略容量、榜单或风控不满足：完整计划仍停止。此次接入没有降低原选股、选债要求。

## 已验证范围

使用临时内存数据库及隔离浏览器检查：目标合计与现金守恒、新钱入池、在途不供买单、平安现金不重复、整手与费用不超预算、未成交基金卖单不能供买单、计划冻结与输入变更失效、旧配置计划失效、账户录入与三种屏幕布局。

2026-09-28验收：509项单元/集成测试通过，Ruff及差异格式检查通过；1512、1440与390像素三种宽度的隔离浏览器检查通过，人工复核平安交易条件与基金订单限价展示。正式规则的旧版本已完整归档，当前文档本地链接已核对。

验证证明的是计算和界面行为，不代表已取得真实交易条件、已完成资金迁移，或证明新组合的未来收益与回撤。没有自动下单、实际申赎、资金转账或真实账户代填。
