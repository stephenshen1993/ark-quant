# 公网行情/基本面数据渠道调研（自用投资系统）

调研日期：2026-06-05
覆盖资产：可转债、A股、公募基金（与当前持仓一致）
目的：系统梳理可接入的数据渠道，定位"哪些免登录、哪些要注册 token、哪些要登录 cookie、哪些付费"，并给出本项目的接入优先级。直接动因是 6/5 东方财富"总市值"接口对 Python 请求被拦、导致策略停摆——这是典型的"单源单点"风险。

---

## 0. 本项目按字段的数据需求

| 资产 | 必需字段 | 当前来源 | 痛点 |
| --- | --- | --- | --- |
| 可转债 | 全市场列表、现价、成交额、转股溢价率、剩余规模、到期日、强赎状态 | AKShare(`bond_zh_cov`)、集思录强赎表、新浪转债日线 | 基础接口字段不全，靠集思录回填；新浪逐只抓有限流风险 |
| 可转债 | 正股动量/波动率（正股历史K线） | AKShare 新浪日线 | 工作正常 |
| 可转债 | **正股总市值**（小市值因子） | **东方财富** `stock_zh_a_spot_em`/`stock_individual_info_em` | **本环境对 Python 请求被拦/限流，已坏多日**，目前用"收盘价×流通股"估算顶替 |
| A股 | 行情、估值、财务（未来策略） | 尚未建设 | — |
| 基金 | 净值、持仓、规模（未来） | 尚未建设 | — |

核心结论：**逻辑已经够用，瓶颈在数据源的稳定性与多样性**。解法是"按字段配多源 + 故障自动切换 + 快照留存"。

## 1. 数据源全景（按接入门槛分类）

### A. 免登录、免费（开箱即用）

| 源 | 接入方式 | 覆盖 | 稳定性 | 备注 |
| --- | --- | --- | --- | --- |
| **AKShare** | `pip`，无 token | 转债/股票/基金/期货/指数，最全 | 中（底层多为东财/新浪/同花顺爬虫，接口字段会变、会被限流） | 已在用。是"广度"主力，但**不要把关键字段单押在它的东财端点上** |
| **BaoStock** | `pip`，`login()` 匿名 | A股日/周/月K、复权、**总股本/流通股本**、估值、分红 | **高（专为量化、稳定、无封IP）** | 强烈推荐做"总市值/股票行情"的稳定第二源；可由 收盘价×总股本 算总市值 |
| **mootdx（通达信本地协议）** | `pip mootdx` | 实时/历史行情、市值（配合总股本）、L1 | 高（直连通达信服务器，**不走东财、不易封**） | 适合实时/盘中；社区推荐的"东财替代"首选之一 |
| **新浪 / 腾讯 直连 HTTP** | 直接请求其行情 API | 转债/股票实时与历史 | 中高（我们管线里新浪一直正常） | 已在用（正股历史走新浪、腾讯做备份） |
| **中证指数 csindex.com.cn** | 网页/Excel 下载 | 中证转债指数等成分与点位 | 高（官方） | 用于策略文档里"中证转债 120 日均线"风控 |

### B. 免费、需注册拿 token（合法、无需爬）

| 源 | 门槛 | 覆盖 | 备注 |
| --- | --- | --- | --- |
| **Tushare Pro** | 注册得 token；**积分制**：`daily_basic`(总市值/流通市值/PE/PB) 需 **≥2000 积分**，5000 积分无频次限制；积分可免费累积（完善资料+签到+社区） | A股行情与`total_mv/circ_mv`、**可转债**(`cb_basic`/`cb_daily`)、**基金**(净值/持仓)、财务、指数 | **本项目最高性价比的一步**：`daily_basic.total_mv` 直接、干净地解决我们的"总市值"痛点；合法 API，不靠爬虫 |

### C. 需登录 cookie（ToS 灰区，仅手动/谨慎）

| 源 | 说明 | 风险 |
| --- | --- | --- |
| **集思录（登录）** | 网页数据更全（强赎进度、双低榜、分类）；**官方无开放 API**；AKShare 已封装了部分集思录数据；另有**付费"可转债评估表"约 36 元/月** | 自动爬取违反 ToS、可能封号；付费表是更稳妥的"富因子"来源 |
| **雪球（cookie）** | 组合、行情、自选；需 cookie | 自动化违反 ToS、易封号；**建议仅手动用，不接入自动管线** |
| **同花顺问财（iwencai）** | 自然语言选股，AKShare 有封装 | 接口不稳定、反爬强 |

### D. 付费/机构（了解即可，自用一般不必）

Wind、Choice(东方财富金融终端)、聚宽 JoinQuant、米筐 RiceQuant、Tushare 付费档。数据质量与稳定性最好，但年费高，个人自用前期不需要。

## 3. 直接解决我们踩的坑：总市值

按"立刻可做 → 最稳"排序：

1. **现状（已落地）**：用新浪历史里的 `outstanding_share` 估算"流通市值"顶替，已固化进策略兜底（`apply_market_cap_estimate`）。口径是流通市值≠总市值，对小市值排序影响有限。
2. **BaoStock（零门槛升级）**：`query_history_k_data` 可取复权价，配合其总股本字段算**真·总市值**；免登录、稳定、不封 IP。可作为东财失效时的第一兜底，口径正确。
3. **Tushare `daily_basic`（注册即长治久安）**：直接给 `total_mv` 与 `circ_mv`，一次调用拿全市场，**最干净**。需 ≥2000 积分（免费可攒）。
4. **mootdx**：实时/盘中场景下的总市值（配合总股本），不走东财。

建议落地顺序：**先接 BaoStock 当稳定兜底（本周）→ 注册 Tushare 攒积分后接 `daily_basic` 当首选（口径最正）**。东财端点降级为"可选备份"，并对其加串行限流（间隔≥1s+抖动）。

## 4. 容错架构建议（让"数据卡点"系统性消失）

1. **按标准字段解耦多源**：每个字段定义"首选→备份链"，任一源挂掉自动切换（项目已有雏形，扩展到上面的矩阵）。
2. **每次保存原始快照到 `data/raw/`**：带数据基准日。任何一天的榜单都能复算，源临时不可用也不至于停摆。
3. **统一限流入口**：对东财类易封端点做串行+随机抖动+会话复用；本机系统代理(Clash 7897)对国内财经站应走直连（`NO_PROXY`）。
4. **字段回归测试**：源字段名变化时不静默跑错（项目已有 strict 模式，继续补样例快照测试）。
5. **口径标注**：像 `market_cap_source` 一样，给每个关键字段留"来源/基准日"列，报告里如实显示。

## 6. 落地路线图（建议顺序）

1. **本周**：接入 BaoStock，作为"正股总市值/股票行情"的稳定兜底（口径正确，免注册）。
2. **你注册 Tushare 后**：接 `daily_basic` 为总市值首选、`cb_basic/cb_daily` 为转债备份源；东财端点降级+限流。
3. **快照层**：每次运行把关键原始数据落 `data/raw/`，带基准日。
4. **股票策略起步**：基于 BaoStock/Tushare 搭股票数据层（与转债共用数据抽象）。
5. **基金**：先用 AKShare 天天基金接净值/持仓，做持仓跟踪。
6. **择时风控**：接 csindex 中证转债指数，落地策略文档里的 120 日均线降仓。
