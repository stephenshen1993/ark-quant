# 更新日志维护规则

本规则给后续 agent 和维护者使用。更新日志面向使用者、维护者和 agent，但页面呈现只保持用户可读的变更流。

## 呈现口径

- 更新日志在本地 Web 看板中展示，入口名称为“更新日志”。
- 页面只展示日期分组、时分、类型、标题和正文。
- 类型只能使用“更新”“优化”“公告”“下线”。
- 页面第一屏直接展示更新流，不做说明型落地页。
- 页面和静态数据中不得出现追溯编号、变更编号、短哈希、影响范围、内部代码分层、验证命令或维护者备注。

## 数据口径

- 第一阶段使用静态 JSON，不进入 SQLite。
- 静态 JSON 的每条记录只允许包含 `date`、`time`、`type`、`title`、`body`。
- 历史补录只以 `git log` 为可信来源。
- 可以把相邻同主题记录保守合并为一条，但正文不能写入标题无法支撑的效果。
- 未来新增对使用者可感知的变化时，应同步追加更新日志。

## 边界

- 更新日志不是投资体系真源，不定义仓位、再平衡、交易执行或策略参数。
- 更新日志不是工程审计台账，不替代规格、票据、代码审查或测试记录。
- 如需记录工程细节，应放入规格、票据、工程文档或决策记录，不放进更新日志页面。
