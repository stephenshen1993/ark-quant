# 更新日志维护规则

## 2026-08-09 当前持仓按市值排序

- 账户页当前持仓改为按持仓市值从高到低展示。
- 市值相同时按证券代码升序稳定排序，行情暂缺的证券排在最后。
- 排序只作用于展示层，不改变用户原始持仓数据。
- 356 项单元测试、Ruff 及 wide/desktop/narrow UI smoke 通过。

## 2026-08-08 迁移账户估值补齐

- legacy 证券账户读取时复用当前估值逻辑，不再把价格和市值硬编码为空。
- 账户页、计划就绪度和计划生成统一消费同一份当前估值；行情不可用时正确返回 `unavailable` 并阻止生成。
- 确认数据仍准确时可持久化恢复后的估值；若有效计划输入发生变化，既有计划会转为 `stale`。
- 355 项单元测试、Ruff 及 wide/desktop/narrow UI smoke 通过。

## 2026-08-08 账户数据更新模型验收

- 账户页改为逐账户当前数据更新，移除全局事实日、roll-forward 与批量保存前端代码。
- 清空全部持仓与清空整个账户使用不同确认意图，持仓清空不修改现金。
- 补齐 legacy 同日配对、并发旧写接口双真相、仅历史回填、readiness fail-closed 和计划生成竞态保护。
- 340 项单元测试、Ruff 及 wide/desktop/narrow UI smoke 通过；迁移核对未发现数据异常。

本规则给后续 agent 和维护者使用。更新日志面向使用者、维护者和 agent，但页面呈现只保持用户可读的变更流。

## 呈现口径

- 更新日志在本地 Web 看板中展示，入口名称为“更新日志”。
- 页面只展示日期分组、时分、类型、标题、正文和影响范围标签。
- 类型只能使用“更新”“优化”“公告”“下线”。
- 页面第一屏直接展示更新流，不做说明型落地页。
- 页面和静态数据中不得出现追溯编号、变更编号、短哈希、内部代码分层、验证命令或维护者备注。

## 数据口径

- 第一阶段使用静态 JSON，不进入 SQLite。
- 静态 JSON 的每条记录必须包含 `date`、`time`、`type`、`title`、`body`，可以包含用户可见的 `scopes` 影响范围标签。
- 历史补录只以 `git log` 为可信来源。
- 可以把相邻同主题记录保守合并为一条，但正文不能写入标题无法支撑的效果。
- 未来新增对使用者可感知的变化时，应同步追加更新日志。

## 边界

- 更新日志不是投资体系真源，不定义仓位、再平衡、交易执行或策略参数。
- 更新日志不是工程审计台账，不替代规格、票据、代码审查或测试记录。
- 如需记录工程细节，应放入规格、票据、工程文档或决策记录，不放进更新日志页面。
