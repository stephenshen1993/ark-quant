# 更新日志维护规则

## 2026-08-10 长钱命名与温度口径修复

- 账户、概览和计划中的两个长钱载体统一显示为“国内长钱”和“海外长钱”，不再混用“长钱投顾组合 / 海外长钱投顾组合”。
- 概览的全市场温度改为读取当前市场温度输入，不再使用账户 context 中历史保存的温度；计划页生成前后都保留温度展示，避免更新到 50° 后又回落或消失。
- 领域边界同步写入 `CONTEXT.md`：温度是市场状态和计划输入，不是账户事实，也不属于任何单个账户。

## 2026-08-09 账户交易计划执行单化

- 主导航新增“榜单”一级入口，放在计划与账户之间；榜单定位为策略信号 / 计划输入，可独立查看、生成和导出股票与转债榜单。
- 计划页只消费榜单结果，不再承担榜单浏览职责，避免计划执行卷宗混入策略信号表格。
- 计划页顶部收敛为单层身份区，状态、数据日、执行日、生成时间和版本只在 masthead 表达一次；删除已生成计划下方重复的状态横线。
- 资金调拨计划和账户交易计划模块只表达模块特有信息，账户状态徽标和账户摘要不再重复全局执行日；日期只在资金可用日或账户交易日偏离全局执行日时出现。
- 展开态表格上方去掉重复的账户名、日期、资金状态和计划名称，只保留账户序号与收起/切换控制；账户摘要负责解释上下文，展开区直接进入交易明细。
- 展开账户交易计划后，固定卷宗条只承担轻量定位，不再重复计划日期、执行日期和资金状态。
- 折叠账户卡片移除大块现金公式，只保留资金前提摘要；完整资金估算过程退到展开后的次级细节。
- 证券交易明细改为一张连续执行表，默认按清仓、减仓、建仓、加仓排序但不插入分组标题；每行显式展示仓位语义、买卖方向和交易数量，交易数量以“数量 单位”的单行数值呈现。移除可见“卖出阶段 / 买入阶段”、 “顺序”列、分组行和逐行价格上限，持仓变化仅作为不占行的计算依据保留。桌面表格改为按执行内容收缩，避免证券代码、名称与买卖、数量、金额之间被无意义空白拉开。
- 计划待执行态压缩为紧凑状态栏，正文改成更连续的执行文档；账户折叠态直接展示资金前提、动作摘要和计划后资金，展开后先看证券交易明细，再看参考价、硬约束和资金估算依据。
- 展开态摘要收敛为一行执行状态，隐藏重复的资金公式和展开提示，让主体空间留给执行行。
- 买入阶段提示按资金状态变化，等待资金、当日调入和资金已具备不再使用同一套文案。

## 2026-08-09 全站信息架构改为概览优先

- 默认入口改为“概览”，负责查看整体配置结构；“计划”只负责下一步资金调拨和账户交易执行。
- 主导航调整为概览 → 计划 → 账户；更新日志降为系统信息入口。
- 概览、账户和计划不再共用顶部状态条，避免把总体情况、数据维护和执行计划混成同一层级。
- 计划条件改为默认组合内轮动，可按需勾选同时进行组合间再平衡。
- UI smoke 闸门同步覆盖新导航、紧凑资金调拨表、账户交易计划展开态和更新日志新几何基线。

## 2026-08-09 资金调拨计划执行要素收敛

- 资金调拨计划改为一张连续表格，只保留调拨路线、调拨金额和资金可用时间。
- 用途、影响、再平衡原因和下游交易说明不进入执行表；调拨金额紧跟路线，桌面行高压缩至约 44px。
- 宽屏浏览器闸门限制单表数量、桌面行高和路线到金额的视觉距离；窄屏沿用同一核心要素并禁止横向溢出。
- 366 项单元测试、Ruff、`git diff --check` 及 wide/desktop/narrow UI smoke 通过。

## 2026-08-09 计划页执行时点与交易明细优化

- 未来执行计划改为“计划待执行”，用单一时间线连接收盘数据日与开盘执行日，并提示未到执行窗口不要交易。
- 稳定计划隐藏重复状态链、生成面板和就绪卡片，主判断显示生成时间与短版本标识。
- 证券代码和证券名称拆列；新计划同时展示当前持仓、目标持仓、本次数量，旧计划缺少字段时保持兼容降级。
- 可转债买入上限随具体订单行展示，长列表增加前后账户切换和可恢复的专注视图。
- 365 项单元测试、Ruff 及 wide/desktop/narrow UI smoke 通过。

## 2026-08-09 账户交易计划执行卷宗

- 正常计划页移除重复生成面板和就绪卡片，紧凑状态链不再用交易笔数表达工作量。
- 账户交易计划增加具体资金前提、互斥展开、可恢复地址状态和滚动时固定的账户卷宗条。
- 交易明细增加参考价基准、非限价说明、可转债成交价上限和股票单只仓位容量保护。
- 过期执行窗口停止展示为当前可执行建议，等待未来资金的账户明确标为当前不可执行。
- 计划执行读模型、页面交互测试、Ruff 及 wide/desktop/narrow UI smoke 通过。

本规则给后续 agent 和维护者使用。更新日志面向使用者、维护者和 agent，但页面呈现只保持用户可读的变更流。

## 呈现口径

- 更新日志在本地 Web 看板中展示，入口名称为“更新日志”。
- 页面只展示日期分组、时分、类型、标题、正文和影响范围标签。
- 类型只能使用“更新”“优化”“修复”“公告”“下线”。
- 页面第一屏直接展示更新流，不做说明型落地页。
- 页面和静态数据中不得出现追溯编号、变更编号、短哈希、内部代码分层、验证命令或维护者备注。

## 数据口径

- 第一阶段使用静态 JSON，不进入 SQLite。
- 静态 JSON 的每条记录必须包含 `date`、`time`、`type`、`title`、`body`，可以包含用户可见的 `scopes` 影响范围标签。
- 历史补录只以 `git log` 为可信来源。
- 可以把相邻同主题记录保守合并为一条，但正文不能写入标题无法支撑的效果。
- 未来新增对使用者可感知的变化时，应同步追加更新日志。

## 边界

- 更新日志不是投资体系真源，不定义仓位、再平衡、交易执行或策略参数。
- 更新日志不是工程审计台账，不替代规格、票据、代码审查或测试记录。
- 如需记录工程细节，应放入规格、票据、工程文档或决策记录，不放进更新日志页面。
