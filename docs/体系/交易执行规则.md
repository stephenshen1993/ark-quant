# 交易执行规则

> 状态：当前真源 v2026-09-28；跨策略执行手册
> 职责：把目标金额和策略榜单翻译为可执行、可检查的资金调拨计划和账户内交易计划。
> 真源范围：计划日期、输入窗口、资金可用性、订单有效性、费用预留、现金不足、部分成交、失败交易、资金回流、暂停条件和计划交付边界。
> 不负责：战略目标、仓位公式、账户 UI 行为、账户内策略筛选参数、策略排名生成逻辑、API、数据库、页面实现或自动下单。
> 最后核对：2026-09-28

## 2026-10-08 统一计划口径（覆盖下文旧参考草案与限价核验要求）

广发、华泰、平安的当期交易计划统一按上一交易日收盘数据计算，供下一交易日开盘执行。计划参考价用于计算委托数量和预计金额，不预测开盘涨跌，也不因平安账户单独增加实时核价或人工确认门槛。行情缺失仍应明确显示，不得编造价格；原有策略硬约束继续适用。

资金调拨计划统一列出各账户经资金账户调入、调出的本期目标，不按账户类型或到账周期隐藏条目。资金账户的当期调出不得超过已有可用余额，未到账回流不计入当期购买预算。通用调拨能力与阶段资金来源顺序分开：当前仍保留广发、华泰现金用于账户内策略，按本期新增投入安排国内长钱优先、海外长钱补足的分批回流。

## 2026-09-29 现金区间（当前生效，覆盖下文旧费用预留口径）

广发、华泰、平安各自的计划后预计可用现金保持在 **300～1,000元**，不另设区间内目标值。该现金计入原有全体系直接现金配置，不增加资产或现金目标。

生成计划不再逐笔扣算手续费及小额摩擦，实际费用从预留现金中扣除；实际扣费后可以略低于300元，下次正常计划再处理，不单独触发证券交易。300元下限只约束未扣费用的计划余额，不是实际成交后的保底承诺。冻结现金不作为该预留余额。

先从已有银行及券商可用现金中留出预留空间，再分配买入预算。原策略生成整手订单后，余额不足时优先少回池，必要时在已有银行现金内补入；超过1,000元则通过回池调拨处理。不得为了现金区间额外买卖证券、预支别的账户未到账回流或突破资金上限；无法满足时明确报告缺口。没有执行条件的空平安账户不预先占用预留资金。

平安佣金费率、最低费用不再是计划门槛。预算与核价分开：系统获取公开代码、交易单位、计划日参考价格生成参考订单；实际委托仍须核对限价与溢价。忽略小额摩擦不等于接受任意溢价。旧费用算法只保留为历史研究/命令行兼容；方舟当前完整计划统一采用本节规则。

## 2026-09-28 阶段配置衔接（当前生效）

全体系预算遵循[仓位与再平衡规则](仓位与再平衡规则.md)中的阶段规则，不使用历史A_exec或温度公式二次分配。原选股、选债、费用及风险纪律继续适用。

平安同一账户承载纳指及501312，各自独立预算。系统可沿前期研究的161130与501312补齐预算草案参考信息，注明来源与日期；不修改实际持仓或宣称最终工具与溢价已获确认。行情失败时保留待用预算，不回收成闲置现金，也不要求用户手填公开行情。以下核验约束针对实际委托，参考草案须明确标注。缺少标的、限价、交易单位、限价成本核验时，受影响方向显示暂不能执行；不擅自假定低溢价、零费用或默认某只纳指工具已获选。限价及其成本核验跟随计划基准日冻结；买入不高于核实限价，卖出不低于核实限价。

资金调拨与具体订单使用同一版本输入。尚未完成的银证转入是下单前提，券商现金回池须核对可取状态，赎回在途不支持即时买入。整手取整和费用后的余额保留现金；实际成交、到账或账户输入发生变化后更新事实再生成。旧配置计划不得继续作为当前可执行计划。

## 1. 执行总原则

```text
固定计划口径
-> 校验输入
-> 计算目标
-> 按动作阈值和当前真实可用资金计算本次动作
-> 分别生成资金调拨计划和账户内交易计划
-> 人工检查
-> 输出计划
```

宁可没有计划，也不要用缺失、混期或不可追溯的数据生成错误计划。

### 1.1 执行层边界

本文件定义跨策略执行纪律：同一个计划日内，资金调拨、股票订单和可转债订单如何共享事实、现金、费用、失败处理和人工检查。它不定义账户页面怎么交互，也不定义股票或转债榜单如何产生。

账户 UI 只能呈现或录入事实，不能因为页面控件方便就改变本文件的现金、费用、订单和暂停规则。策略特定排名、筛选、硬风险字段和退出语义只在执行规则依赖它们时被引用；具体规则以对应策略文档为准。

当前引用关系为：

| 执行事项 | 本文件职责 | 专属规则来源 |
| --- | --- | --- |
| 体系级资金调拨 | 使用已经确认的目标、偏离、现金池和触发结果生成本次可执行动作 | [仓位与再平衡规则](仓位与再平衡规则.md) |
| 小市值股票订单 | 使用可执行策略预算、费用、100 股单位、订单下限和执行顺序生成订单 | [小市值股票策略规则](../策略/小市值股票策略规则.md) 负责榜单、退出和策略风险 |
| 多因子可转债订单 | 使用可执行策略预算、费用、10 张单位、价格硬上限和执行顺序生成订单 | [多因子可转债策略规则](../策略/多因子可转债策略规则.md) 负责榜单、过滤和风险字段 |
| 账户 UI 或 API | 只作为事实录入和计划展示载体 | 工程实现说明，不是投资规则真源 |

账户内交易定额的任何算法实现还必须满足 [交易计划验收契约](交易计划验收契约.md)；该契约只定义验收场景和输出证据，不替代本文件或策略规则中的交易规则。

股票与可转债账户共用 [账户内交易定额规则](账户内交易定额规则.md)：两者均以合格 Top 20 为普通交易计划前提，统一采用理论等权两倍的 10% 单标的风险防线，并把无归因可投资余现作为零权重仓位参与整体偏离比较。

### 1.2 人在回路的执行治理

当前安全形态为人在回路，而不是自动交易：

```text
人决定何时触发计算
-> 工具按体系规则生成资金调拨计划和交易计划
-> 人工复核计划与真实账户
-> ark-quant 的本次职责结束
-> 人在工具之外决定是否以及如何执行
```

触发权和最终执行权属于人，但计划计算权仍属于已经确认的体系规则。ark-quant 保留生成计划所需的输入和原始输出即可；MVP 不追踪计划是否执行、怎样执行、部分成交或人工调整，也不要求把执行结果写回系统。人工实际动作不会反向改变本次体系计划，下一次计划直接使用届时最新的真实账户和持仓事实重新计算。

当前不接入 QMT 等自动交易机制，不向券商或基金平台自动提交订单。未来是否引入任何自动触发、自动下单或自动申赎能力，必须重新完成安全边界、权限、异常处理和人工撤回机制的独立评审，不能作为普通工程升级默认开启。

### 1.3 一个计划入口，分步人工执行

工具无论以按钮、命令或脚本形式触发，都只能生成或刷新一份完整计划，统一给出资金调拨与账户内交易草案；这只是一次只读计算，不是一键执行。资金调拨计划依赖当前账户事实及阶段规则；基金核价条件只影响订单，不阻塞资金预算；股票或转债交易计划只在同一计划日再合并已经成立的调拨结果、对应榜单、该账户持仓和真实可用现金。

人工执行顺序为：先完成当下已经成立的资金调拨；再在各自账户内按真实可用现金执行股票、转债或场内基金订单；任何卖出、赎回、申购或转账的未到账部分都不进入同次可用现金。每个关键人工动作后，如需继续操作，重新读取最新事实并生成新计划。MVP 不保存“下一步”、不自动续接旧计划，也不提供一键提交多个账户或平台动作的能力。

## 2. 计划日期与输入窗口

| 概念 | 含义 |
| --- | --- |
| 计划日 | 最近已完成交易日，股票与转债榜单对应的数据日 |
| 适用开盘日 | 计划准备实际执行的交易日 |
| 计划输入窗口 | 从计划日到适用开盘日之间可接受事实快照的窗口 |
| 触发类型 | 常态检查或临时追加检查 |

规则：

- 股票、转债榜单和基金核价条件必须明确计划日；温度只供观察。
- 常态和临时检查只影响何时启动计算，使用完全相同的目标、阈值、策略和执行约束。
- 正式计划使用最近已完成交易日的完整收盘数据，原则上只指导下一个交易日开盘开始执行。
- 若人在适用开盘日未能使用该计划，计划不能自动顺延为后续交易日的有效指令；下次准备执行前应按新的最近收盘数据重新生成。ark-quant MVP 不判断旧计划已经执行多少，也不维护跨日执行状态。
- 账户和持仓只保存事实状态、口径日期和录入时间，不保存人为交易归属日。计划输入窗口以口径日期为准；录入时间只用于区分同一口径日期下的先后版本，不能把旧口径事实伪装成新事实。
- 计划使用输入窗口内最新、完整且可追溯的事实快照。
- 同一天多次保存时，优先使用口径日期更接近适用开盘日、更新时间更新且完整度更高的记录。
- 旧数据只能作为显式兼容回退，不能默默冒充新输入。
- 账户、持仓或本次计划条件一旦保存新事实，基于旧事实生成的当前订单立即失效；同日榜单仍可复用，但必须重新计算资金调拨和订单。MVP 不把派生订单当作不可变的成交记录。
- 温度短期未更新不单独阻止阶段固定目标计划，不能用它替代交易日历。

## 3. 必需输入

- 全部账户的真实持仓、可用及冻结现金、待迁移投顾持有余额与赎回在途、事实日期与版本。
- 同一计划日的股票和转债榜单、策略参数及必要风险字段。
- 平安各基金方向的代码、核实限价及日期、最小交易单位和该价格成本已核验状态。

金额与资金流语义见[投资记录与绩效口径](投资记录与绩效口径.md)。受影响基金方向条件不足时保留目标缺口，不推定零费用或低溢价。

## 4. 资金可用性

统一按目标差额生成方向预算。股票、转债当前金额取证券市值，直接现金归全体系现金；账户内本次策略预算等于证券市值加本轮预算净增减，不再经过A_exec二次分配。

即时银行转入总额不超过真实可取现金；券商已有可用资金只抵扣本账户买入需求。现金10%为整轮终态，允许使用已有现金桥接并等待成立的释放方案回补，但未成交或未到账款不是新增购买力。释放失败时更新事实重算。

同一平安账户可能同时存在一个方向减配和另一个方向增配。不能用尚未成交卖单抵消当前需落实的买入资金；显示转入与回池的各自条件。整手和费用后的可释放金额才是回池上限，回池仍须核实券商可取状态。

股票订单只能使用：

- 股票承载账户原有可用现金。
- 资金账户实际调入后的可用现金。
- 股票账户内部卖出实际释放的现金。

转债订单只能使用：

- 转债承载账户原有可用现金。
- 资金账户实际调入后的可用现金。
- 转债账户内部卖出实际释放的现金。

冻结现金属于资产，但不能用于下单或调拨。不能由浏览器或命令行任意传入一个现金数覆盖事实账户。

同一策略、同一承载通道内的计划卖出所得，可以按计划日收盘价估算并纳入同一份账户内买入计划。这是将策略轮动合并为一组净订单，不是预支跨账户未到账资金。计划按以下顺序展示：

```text
必要退出和其他净卖单
-> 同一承载通道内的净买单
```

这个顺序是对人工执行的计划约束，不使 ark-quant 承担成交跟踪或步骤状态管理。若人实际未完成计划卖出，不能超过届时真实可用现金强行执行买单。

订单金额和卖出所得继续使用计划日收盘价估算，不为下一交易日开盘误差额外拍脑袋预留固定百分比现金。必要费用按以下统一粗略口径从可用资金中扣除：

```text
股票计划费用预留 = 5 元 × 非零股票订单数 + 计划卖出金额 × 0.06%
可转债计划费用预留 = max(10 元, 计划总成交额 × 0.01%)
```

粗略预留只负责防止计划透支，不追求逐券商、逐市场复刻实际费用；法定税费结构变化时应更新口径。交易单位和订单下限形成的自然余现也可以吸收部分价格误差，二者都不是账户内现金目标。实际成交价、未完全成交和人工如何调整属于 MVP 之外的执行事实；若开盘时真实现金不足，按计划生成时的买入优先级依次执行，只能缩减或跳过原计划买单，不能透支、借款、突破届时真实可用现金或增加计划外标的。下一次计划以最新真实持仓和现金重算。

计划生成后、人工执行前若出现停牌、无法成交、ST、新强赎风险或其他已经能够确认的不可买状态，跳过对应买单，不临时增加榜单外替代对象；其他原计划买单仍可按既定顺序在真实可用现金范围内执行。计划日之后普通价格变化是否触发新的策略过滤，只服从对应策略已经明确的执行语义，不能由执行层临时增加条件。

股票和可转债策略均不设账户内现金目标。剩余现金还能形成合规买单时，只有该买入不扩大正式的 Top 20 等权目标，才继续分配；若继续买入会扩大等权误差，可以保留现金并明确标注 `equal_weight_priority`。交易单位、普通订单下限、必要费用、冻结、不可交易或计划与实际执行价格差异所产生的自然残余现金同样必须分别归因。

资金经统一现金池流转，不保留原始来源或未来用途标签。资金不足按有效缺口比例分配，分配后不足1000元留在现金，不递归加规则。目标缺口、预算动作与实际完成金额分别记录。

实际卖出、赎回或调出金额后来进入现金池时，它们只成为新的现金事实。MVP 不保留这些资金、不绑定旧计划中的买入用途，也不维护“等待到账后继续”的未完成状态。下一次检查按当时的最新事实重新计算。

次交易日或更晚回流的资金，只有在真实到账、解除冻结并由人保存为新的账户事实后，才进入下一次计划的可用现金。回流前不得作为同次买入预算；回流后也不自动继承旧计划的去向、优先级或未完成缺口。

部分成交或执行失败按事实处理：

- 来源卖出、赎回或转账失败时，不得用原计划预计所得继续完成尚未获得现金支持的买入；已经使用原有真实现金完成的合规动作不强制撤销。
- 来源只部分到账时，只把实际到账金额计入新的可用现金，不沿用原计划的剩余额度。
- 去向申购、转账或买入失败时，已经释放或到账的资金留在其实际所在账户，不为了恢复计划比例临时改买其他对象。
- 任一动作未执行、部分执行或成交金额变化后，旧计划中的未完成部分不成为债务或自动待办；下一次由人触发时按最新真实余额、持仓和可执行状态重新生成。

因此，MVP 只需要展示完整理想金额、部分可执行金额、当前可立即执行金额，以及因资金尚未到账而未进入本次动作的差额；该差额不是待办。MVP 不承担成交回报跟踪、失败回滚或跨计划续跑。



## 5. 股票订单

生成前必须确认股票榜单、持仓、账户总资产和可用现金均有效，并已经考虑调拨后的实际可用现金。

当前执行约束：

- 买入按 100 股整数倍。
- 卖出必须服从 [小市值股票策略规则](../策略/小市值股票策略规则.md)。
- 涨停、停牌、退市、ST 等不可正常交易标的不得作为买入对象。
- 目标持仓为策略榜单 Top 20 等权；单只目标金额为本次可执行小市值股票策略预算的 `1/20`。
- 单只股票计划持仓金额按计划日收盘价估算，硬上限为扣除候选费用前、本次已冻结可执行小市值股票策略预算的 `10%`。`10%`只拦截灾难性集中，不取代 `5%`等权目标；手续费不反向缩小该上限。
- 普通净订单下限为 `max(1000 元, 单只目标金额 × 10%)`；普通净订单未达到下限时可以暂不执行。
- `1000 元`是当前普通股票订单的最低经济尺度，`单只目标金额 × 10%`用于防止资金规模扩大后固定金额退化为噪声微调；两者均为形成期执行参数，不是战略常数。
- 排名退出、硬性风险退出、清空尾仓和无法拆分的必要卖出不受普通净订单下限约束。
- 取整、必要费用和普通订单下限产生的小额现金可以保留；不能把资金调拨偏离阈值直接套到账户内订单，也不能以等待未来调拨为由长期保留大额现金。

股票目标手数依照 [账户内交易定额规则](账户内交易定额规则.md) 的全局离散定额产生，不从当前持仓出发逐只强行凑满。策略特有的 100 股单位、普通订单下限、股票买入资格与必要卖出作为该规则的硬约束；固定 Top 20、10% 风险防线、费用预算和候选比较顺序不得被股票实现另行改写。得到完整目标手数后，再用“目标手数 - 当前手数”计算每只股票的一笔净订单；资金预算变化、策略轮动和当前持仓在这里一次合并，不能先按旧预算轮动、再为调拨重复买卖。出现在 Top 20 但持仓里没有的标的建仓；持仓里有但掉出 Top 20 的标的清仓；已持有且仍在 Top 20 的标的允许按目标态加仓或减仓微调，但减仓后仍保留正持仓，不因普通再平衡或资金调拨清仓。必要退出先保留，普通净订单再应用普通订单下限；低于下限的普通订单本次暂不执行。

净买单按计划生成时相对单只理论目标金额的低配程度从高到低排列，低配程度相同时策略排名更高者优先。执行时真实现金不足，当前买单可以向下缩减到 100 股整数倍；缩减后低于普通订单下限，或连 100 股都无法买入时，跳过当前订单并继续检查后续原计划买单。只有剩余全部原计划股票买单都无法形成合规订单时，才停止买入；不能临时增加榜单外标的。

生成目标手数前必须检查 Top 20 的可执行性：

- 若本次可执行策略预算连 Top 20 每只股票各买入 100 股都无法覆盖，则 Top 20 目标在当前资金规模和价格下不可执行，暂停生成股票交易计划并明确告警，不能静默退化为少于 20 只。
- 若总预算足以覆盖 Top 20 的最低交易单位，某只股票 100 股金额高于单只理论目标、但不超过本次可执行策略预算的 `10%`，计划仍保留 Top 20 目标，同时明确提示该标的会因交易颗粒度产生显著不等权；不能擅自换股或隐藏偏离。
- 若某只目标股票最低 100 股按计划日收盘价估算已经超过本次可执行策略预算的 `10%`，说明当前资金规模无法承载该 Top 20 目标，暂停普通股票交易计划并报告容量冲突；不自动换成第 21 名或临时改变目标集合。

已有持仓在计划日超过 `10%`时，集中度减持优先于普通高配修复，目标仍是回到 `5%`等权附近；该卖单不受普通订单下限约束。若当前持仓包含零股余数，目标持仓保留同一余数，使实际减仓量仍为 100 股整数倍。若因停牌、涨跌停等原因无法卖出，只报告真实集中风险并在下一次按事实重算，不卖出其他股票抵消，也不假设上限已经恢复。

## 6. 转债订单

生成前必须确认转债榜单、持仓、账户总资产、可用现金和关键风险字段有效，并已经考虑调拨后的实际可用现金。

当前执行约束：

- 买入按 10 张整数倍。
- 强赎、价格、剩余规模、成交额、正股风险等检查服从 [多因子可转债策略规则](../策略/多因子可转债策略规则.md)。
- `130 元`同时是计划日候选过滤线和新增买入硬上限：只有计划日收盘价与实际可成交价格都低于 `130 元`才允许买入；实际价格等于或高于 `130 元`时跳过该买单，不重排榜单、不新增替代转债，继续检查其他原计划买单。
- 已有持仓盘中达到或超过 `130 元`不触发临时卖出，下一次完整策略检查再按已完成交易日收盘数据处理。
- 不为了凑目标买入风险字段缺失的转债。
- 基础目标持仓为策略榜单 Top 20 等权；单只目标金额固定为可转债基础目标金额的 `1/20`。合格候选不足 20 只时，暂停普通转债交易计划并明确报告容量冲突，不将未配置金额留作安全阀或重新均分。
- 净卖单优先级为：硬风险或基础过滤失效、有效候选排名跌出 Top 20、单债超过基础目标金额的 `10%`、Top 20 内高于 `5%` 等权目标的普通减持。排名跌出 Top 20 即卖出，不另设排名缓冲区间。
- 不另设普通订单金额下限；只要一笔合规的 10 张订单不恶化第一层等权误差，就继续在等权最优集合内按正式字典序使用资金。
- 10 张是可转债的自然执行单位，金额通常已接近当前统一考虑的千元级经济尺度；不再叠加精确的 `1000 元`门槛，避免对同一笔订单重复过滤。
- 只有等权优先、不足以完成下一笔合规 10 张订单、必要费用、成交失败、冻结或结算状态产生的现金可以保留，不以摩擦成本为由主动留下大额现金。

可转债同样依照 [账户内交易定额规则](账户内交易定额规则.md) 的全局离散定额产生，但不增加股票普通订单下限。策略特有的 10 张单位、`130 元`买入上限、风险过滤与必要卖出作为该规则的硬约束；固定 Top 20、10% 风险防线、费用预算和候选比较顺序不得被转债实现另行改写。得到完整目标手数后，再与当前持仓合并为每只转债的一笔净订单。出现在 Top 20 但持仓里没有的转债建仓；持仓里有但掉出 Top 20 的转债清仓；已持有且仍在 Top 20 的转债允许按目标态加仓或减仓微调，但减仓后仍保留正持仓，不因普通再平衡或资金调拨清仓。必要卖出按既定优先级展示在前，净买单在后。

净买单同样按相对固定理论目标金额的低配程度从高到低排列，低配程度相同时策略排名更高者优先。执行时真实现金不足，当前买单可以向下缩减到 10 张整数倍；连 10 张都无法买入时，跳过当前订单并继续检查后续原计划买单。只有剩余全部原计划转债买单都无法形成 10 张订单时，才停止买入；不能临时增加榜单外转债。

若可转债可执行目标金额连 Top 20 每只合格目标转债各买入 10 张都无法覆盖，则当前资金规模无法承载该目标集合，暂停生成转债交易计划并明确告警。这个检查只判断交易单位可执行性，不得据此放宽风险过滤或用少于 20 个目标静默退化。

当前股票与转债代码均使用共享等权字典序 MILP，并必须产出共同规则规定的唯一比较结果；任何策略适配器不得回退到目标态贪心或局部交换。实现证据与剩余展示差距见 [交易计划定额验收差距](../工程/交易计划定额验收差距.md)。

## 7. 暂停与局部不能执行

账户事实或估值缺失、事实日期超出窗口、策略榜单缺失或混期、必要风险字段不完整、原股票或转债策略的容量约束不能满足时，不输出可执行的完整计划。

预算目标合计必须等于全体系总资产；直接现金、投顾余额和在途不得重复。即时调拨不得超过银行现金，任何订单不得预支未落实资金或使用家庭应急资金。

基金代码、限价、交易单位或成本核验缺失时，该方向保留目标并明确不能执行，不虚构委托，也不把缺口自动改配其他资产。旧策略版本、失效输入或过期执行窗口下的计划不能继续执行。

温度只供观察，缺失不单独停止阶段配置。

## 8. 执行前人工检查

- 计划日、适用交易日和输入版本有效，账户事实仍与真实账户一致。
- 先落实资金前提，实际可用余额足够支付订单与费用；待到账回流不是现金。
- 股票、转债继续满足原策略交易单位、经济下限、Top20与10%单标的防线、转债实际买价低于130元等规则。
- 场内基金代码与方向一致，限价和溢价成本已核实；买入不高于限价，卖出不低于限价。
- 两只基金不重复使用平安现金；投顾按平台赎回条件操作，在途与到账只记一次。
- 停牌、风险变化、失败或部分成交后不临时增添替代标的；更新事实后重新生成。

原股票、转债费用预留与账户内定额细节见第4至6节及[账户内交易定额规则](账户内交易定额规则.md)。

## 9. MVP 交付边界

ark-quant 当前交付物止于：

```text
本次计划输入
资金调拨计划
股票交易计划
可转债交易计划
平安场内基金交易计划
本次未补足的有效低配缺口及原因
暂停原因和人工检查项
```

资金调拨计划对每个相关策略或组合对象至少列出：对象名称、当前承载通道、当前金额、阶段目标金额、完整净调整缺口、阈值判断、本次调拨金额和未补足原因。这些字段用来区分“理想中心”与“本次真实能做的动作”，不组织成资金来源链或跨计划待办。

股票和可转债交易计划还应分别列出：本次可执行策略预算、估算价格基准日、现有可用现金、本次调入与调出、账户内计划卖出所得、粗略费用预留及计算基数、理论目标金额、目标手数、当前手数、计划后估算权重、按执行顺序排列的净卖单与净买单、无法继续分配的自然残余现金及原因，以及交易单位可执行性或显著不等权告警。股票计划还必须列出单只 `10%`硬上限检查和容量冲突；可转债买单还必须明确标注实际买入价低于 `130 元`的硬上限。

MVP 不负责记录实际成交、未成交、部分成交、费用、滑点、实际申赎、跨日进度或计划放弃原因，也不替代有知有行投资账本。下一次计划以届时的真实账户、持仓和现金快照为新事实，独立重新计算；旧计划只是一份历史计划输出，不自动成为下一次计划的待办任务。

## 冻结计划与盘中行情

完整计划保存生成时的账户估值、参考价和订单。单纯读取时行情变动不作废冻结计划；持仓数量、现金等原始账户事实变更仍使其失效。缺失估值补齐时须重算，执行日窗口与价格守卫继续生效。基金参考订单不视作限价或溢价已确认。

## 分批赎回的执行先后

资金表中的“有条件赎回参考上限”须在本轮实际净新增买入确认后申请，国内长钱优先。实际净新增投入扣除已有赎回在途后，再受来源账户剩余可赎余额约束；少买少赎、未买不赎。该条件动作不增加本期资金池可用额，不是赎回已提交或款项已到账的事实。

资金表显示资金池期初可用、本期立即调出、调出后余额；预计回池与已有现金分开。用户更新到账事实后可重算下一批配置，不机械等待周度轮动。
