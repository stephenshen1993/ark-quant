# 账户 & 交易页面重构 — 2026-07-02

## 问题

1. 温度和日期属于策略层参数（T 日收盘数据），但放在账户页，归属不清
2. 温度只管资金分配，排名只依赖策略因子，两者唯一共享的是"T 日"这个日期
3. 榜单和交易计划分两个页面，但排名唯一用途就是生成计划，切来切去没必要
4. 账户页三种数据三种保存方式（手动/自动/防抖），落库时机混乱
5. 现金余额防抖自动落库，持仓需手动保存——不一致

## 新页面结构

导航从三个（账户总览 / 交易计划 / 榜单）合并为两个：

```
账户     ← 纯账户数据：资产、持仓、现金
交易     ← T 日数据 + 资金分配 + 转债 + 股票
```

### 账户页

- 移除温度和日期
- 每个账户：总资产（只读/派生）、持仓明细、可用现金
- 统一保存：每个明细区一个"保存"按钮
- 现金余额改为手动保存（去掉 debounce 自动存）
- 资产占比条保留

### 交易页

```
┌─ T 日收盘数据 ─────────────────┐
│ 日期 [ ]  温度 [ ]°             │
│ (策略基准日)  (用于资金分配)    │
└────────────────────────────────┘

┌─ ① 资金分配 ──────────────────┐
│ 资金调拨指令…                   │
└────────────────────────────────┘

┌─ ② 转债 ──────────────────────┐
│ [运行策略] → 排名 → [生成订单]  │
└────────────────────────────────┘

┌─ ③ 股票 ──────────────────────┐
│ [运行策略] → 排名 → [生成订单]  │
└────────────────────────────────┘
```

- T 日数据块：日期 + 温度，统一保存，作为策略运行的基准日
- 日期改变时，排名查询切换到对应日期
- 温度改变时，资金分配重新计算
- ②③ 折叠已见排名，展开见订单详情

## API 变更

| 变更 | 说明 |
|---|---|
| `/api/account/snapshot` | 移除 temperature 字段 |
| `/api/plan` | 日期和温度作为独立查询参数，不再从 account snapshot 取 |
| `/api/rankings/{strategy}/run` | 接收 `data_date` 参数，可指定策略基准日 |

## 不做

- 不引入新依赖
- 不改 DB schema（temperature 字段保留但不再在账户页展示）
