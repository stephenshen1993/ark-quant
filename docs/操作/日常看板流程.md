# 看板日常使用流程

> 用途：把每天盘后或次日盘前使用 Web 看板生成计划的动作固定下来，避免遗漏账户现金、持仓更新或策略数据。

## 适用时间

推荐在以下时间使用：

- 盘后：当天收盘数据稳定后生成次日计划。
- 次日盘前：确认账户现金和策略输出仍然有效。

本流程的日期口径是：基于 T 日收盘数据，生成 T+1 日开盘可执行计划。

可转债策略对交易时段有保护逻辑，交易时段内不要临时生成新的候选结果。

## 一、启动看板

```bash
source .venv/bin/activate
python3 run_app.py
```

打开：

```text
http://127.0.0.1:8000
```

## 二、更新账户状态

在“账户总览”完成：

1. 进入广发账户，录入股票账户可用现金。
2. 进入华泰账户，录入转债账户可用现金。
3. 进入长钱账户，录入国内长钱总资产。
4. 进入资金账户，录入现金池余额。
5. 进入海外长钱，录入海外长钱总资产。
6. 返回列表页，检查总资产和各账户占比。

全市场温度保存为本地快照，交易页默认复用已保存温度；需要刷新温度时才访问有知有行官网。生成交易计划时，温度快照、转债榜单和股票榜单必须指向同一个计划日；账户和持仓只保存事实状态，交易页取计划输入窗口内最新事实快照。任一关键输入缺失或不在适用窗口内，都会暂停生成计划。

录入时使用人民币金额，单位为元。页面显示 `¥`，输入框只填数字。

## 三、确认持仓

在广发账户和华泰账户详情页确认：

- 持仓代码正确。
- 名称正确。
- 股数或张数是实盘最新数量。
- 删除已经清仓的标的。
- 新买入的标的已经添加。

确认后点击“保存持仓”。

## 四、运行策略

生成可转债榜单和订单：

```bash
python3 -m strategies.cb_rotation.run
```

生成小市值股票榜单和订单：

```bash
python3 -m strategies.stock_smallcap.run
```

如果只是快速检查，可以使用 README 中的 `--max-bonds` 或 `--max-universe` 冒烟参数；正式计划不要使用抽样结果。

## 五、检查榜单

在“榜单”页确认：

- 数据基准日正确。
- 适用开盘执行日正确。
- 转债 Top 20 有结果。
- 股票 Top 20 有结果。

榜单只代表候选池，不直接代表最终交易。

## 六、检查本期计划

在“本期计划”页确认：

- 没有缺失数据提醒。
- 资金调拨步骤合理。
- 转债订单的卖出、减仓、买入、加仓方向合理。
- 股票订单的卖出、买入、加仓、减仓方向合理。
- 买入端金额不超过可用现金和预计调拨后现金。
- 可转债张数符合 10 张整数倍要求。
- 股票股数符合 100 股整数倍要求。

## 七、执行前把关

下单前至少检查：

- 使用的是最新账户快照。
- 使用的是最新实盘持仓。
- 海外长钱没有被纳入国内再平衡卖出来源。
- 长钱账户调拨没有因为小额偏离频繁申赎。
- 先卖出、再调拨、再买入，避免现金不足。
- 策略报告没有明显数据源失败或口径漂移提醒。

## 八、执行后收尾

实盘执行完成后：

1. 回到广发账户，更新股票持仓数量。
2. 回到华泰账户，更新转债持仓数量。
3. 更新两个账户可用现金。
4. 更新资金账户余额。
5. 点击“保存持仓”和“保存账户”。

执行后的持仓和账户快照是下一次计划的起点。

## 异常处理

### 报价失败

如果持仓详情页价格为空或持仓资产异常，不要直接按页面金额执行计划。先检查网络、数据源或稍后重试。

### 本期计划缺少订单

重新运行对应策略。如果仍然缺失，查看 `outputs/` 和 `logs/` 中的最新报告与日志。

### 页面金额和券商不一致

可用现金以券商为准。持仓资产用于估算和再平衡，允许与券商显示存在小额口径差异。

### 实盘部分成交

只把已经成交的部分写入持仓和现金。未成交部分不要提前写入，否则下一次计划会误判真实仓位。
