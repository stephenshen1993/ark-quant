# 交易计划定额验收差距

> 状态：当前实现审计，非规则真源
> 职责：逐项比较 [交易计划验收契约](../体系/交易计划验收契约.md) 与当前的股票、转债和计划展示实现，记录可验证的实现差距。
> 真源范围：代码事实、测试覆盖与实现缺口。
> 不负责：改变投资规则、选择算法、设定参数或替代验收契约。
> 最后核对：2026-08-11

## 1. 审计结论

当前系统已经能把账户可用现金、当日调拨、同账户卖出估算额和买入估算额闭合为一份账户交易计划，也能按“卖出后买入”组织人工执行顺序。股票与转债现共用离散目标状态内核：共同 Top 20、10% 容量冲突和余现虚拟仓位比较已经落地，转债不再在向下取整后直接停止；资金调拨层也不再把转债候选不足改写为现金目标。

但该内核目前是按全局指标选择下一手的确定性改良搜索，尚未证明等价于穷尽式整数最优。华泰账户的大额计划后余额的直接缺陷已经修复；可审计的穷尽式全局最优仍是后续差距。

## 2. 按验收契约的覆盖情况

| 验收项目 | 状态 | 代码事实 | 差距或风险 |
| --- | --- | --- | --- |
| 一份完整、开盘前冻结的计划 | 已覆盖 | 生命周期与执行读模型输出一份资金调拨加账户交易计划；执行日变化不在盘中重算。 | 需在后续共享内核改造中保持。 |
| 当日调入与未来到账分离 | 已覆盖 | 调拨动作带 `available_on`；账户计划分别表达资金前提与日期。 | 无算法缺口。 |
| 同账户卖出回款计入预算 | 已覆盖 | 定额器把非目标持仓卖出作为必要回款；账户摘要以卖出额减买入额和费用闭合余额。 | 必要卖出原因的结构化解释仍不完整。 |
| 必要卖出先于买入 | 已覆盖 | 执行读模型按卖出、买入分阶段；两个策略定额器均先生成退出或非目标持仓卖单。 | 必要卖出原因的结构化解释仍不完整。 |
| 股票 Top 20 容量冲突 | 已覆盖 | `size_stock_orders` 在合格候选少于 20 时阻塞；股票定额器检查每个目标最低 100 股与单券上限。 | 共享内核应保留该能力而非只依赖调用入口。 |
| 两账户 Top 20 容量冲突 | 已覆盖 | 共同定额内核要求恰为 20 个候选；股票、转债入口和资金调拨层均以容量冲突失败关闭，不再使用转债安全阀降级。 | 最低交易单位可承载性仍须由账户定额器在冻结报价下判定。 |
| 离散单位与不透支 | 已覆盖 | 股票使用 100 股、转债使用 10 张；共同内核在每个候选上扣除正式粗略费用后校验不透支。 | 实际成交费用和滑点仍属于执行日事实。 |
| 取整后的余现使用 | 已部分覆盖 | 共同内核把可投资余现作为零权重虚拟仓位，只有新增一手改善最大整体偏离、全体偏离或余现时才继续买入；股票和转债共用该过程。 | 当前为确定性改良搜索，尚未证明全部离散组合的全局最优。 |
| 不为使用余现制造普通卖单 | 已覆盖 | 股票余现阶段仅新增买入；转债当前没有余现阶段。 | 未来共享内核须将必要卖出固定为输入，不能把卖出变成优化变量。 |
| 费用预留进入现金约束 | 已覆盖 | 股票采用“5 元 × 非零订单数 + 卖出额 × 0.06%”；转债采用 `max(10 元, 总成交额 × 0.01%)`。候选比较和计划现金摘要均扣除该费用。 | 费用只作粗略预留，不替代实际成交费用。 |
| 统一单标的风险防线 | 已覆盖 | 两策略均由共同内核使用 10% 上限。 | 计划展示仍需补每只标的的上限校验与计划后权重证据。 |
| 执行日价格与资格护栏 | 部分覆盖 | 计划展示层为转债买入提供低于 130 元的执行护栏；规则规定执行日跳过、缩减而不替补。 | 需要把护栏、原计划买入优先级和余额原因纳入统一输出证据。 |
| 计划后权重、余现原因和摩擦说明 | 缺失 | 当前账户计划提供期初现金、调拨、预计买卖与计划后现金。 | 未输出所有标的计划后权重、理论等权、费用、自然余现原因或组合级取舍依据。 |
| 组合级唯一解 | 部分覆盖 | 共同内核按最大整体偏离、全体偏离、余现、费用和订单数依次比较，并以冻结榜单顺序稳定打破当前平局。 | 尚未证明改良搜索等价于全局离散最优。 |

## 3. 直接证据

- [共同定额内核](../../strategies/discrete_target_sizing.py) 对两个策略统一实施 Top 20、10% 上限、容量冲突和余现虚拟仓位比较；高价一手跨越理论等权的场景已有回归测试。
- [转债定额器](../../strategies/cb_rotation/size_orders.py) 和 [股票定额器](../../strategies/stock_smallcap/target_sizing.py) 分别只保留交易单位、订单门槛与策略订单字段适配。
- [订单定额编排](../../app/order_sizing.py) 与 [现金汇总](../../app/plan_service.py) 将内核估算费用带入计划后现金；执行读模型和页面的逐笔费用展示仍待补充。
- [计划执行读模型](../../app/plan_execution_read_model.py) 正确展示了“期初 + 调拨 + 卖出 − 买入”的账户现金方程，但该方程同样不含费用与计划后权重。

## 4. 改造前必须保留的行为

1. 资金调拨计划前置；订单定额只能消费执行日可用资金，不能为了订单回推或等待未来调拨。
2. 卖出阶段先于买入阶段；未实际获得的资金不得支持人工继续买入。
3. 计划只指导下一个交易日，盘中不重算、不更换榜单外标的；执行差异进入下一次真实账户事实。
4. 容量冲突、冻结、费用、不可交易和不足下一手必须与普通可投资余现分开说明。
