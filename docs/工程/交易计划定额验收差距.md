# 交易计划定额验收差距

> 状态：当前实现审计，非规则真源
> 职责：逐项比较 [交易计划验收契约](../体系/交易计划验收契约.md) 与当前的股票、转债和计划展示实现，记录可验证的实现差距。
> 真源范围：代码事实、测试覆盖与实现缺口。
> 不负责：改变投资规则、选择算法、设定参数或替代验收契约。
> 最后核对：2026-08-15

## 1. 审计结论

当前系统已经能把账户可用现金、当日调拨、同账户卖出估算额和买入估算额闭合为一份账户交易计划，也能按“卖出后买入”组织人工执行顺序。股票与转债已经共用同一个等权字典序 MILP，在全部可行组合中依次比较目标持仓平方等权误差、最大整体偏离、总绝对偏离、余现、费用和订单数；Top 20、10% 容量冲突、费用取整与失败关闭也由同一求解核心实施。

两个账户均已补齐可审计的全局最优、MIP gap、正式费用取整和确定性平局；股票额外覆盖普通卖出边界、低价标的跨多手订单门槛与带零股余数的风险减仓，转债额外覆盖正常等权减仓和组合级最低费用。后续主要差距是在计划页面展示逐标的权重、风险上限口径和余现归因。

## 2. 按验收契约的覆盖情况

| 验收项目 | 状态 | 代码事实 | 差距或风险 |
| --- | --- | --- | --- |
| 一份完整、开盘前冻结的计划 | 已覆盖 | 生命周期与执行读模型输出一份资金调拨加账户交易计划；执行日变化不在盘中重算。 | 需在后续共享内核改造中保持。 |
| 当日调入与未来到账分离 | 已覆盖 | 调拨动作带 `available_on`；账户计划分别表达资金前提与日期。 | 无算法缺口。 |
| 同账户卖出回款计入预算 | 已覆盖 | 定额器把非目标持仓卖出作为必要回款；账户摘要以卖出额减买入额和费用闭合余额。 | 必要卖出原因的结构化解释仍不完整。 |
| 必要卖出先于买入 | 已覆盖 | 执行读模型按卖出、买入分阶段；两个策略定额器均先生成退出或非目标持仓卖单。 | 必要卖出原因的结构化解释仍不完整。 |
| 股票 Top 20 容量冲突 | 已覆盖 | `size_stock_orders` 在合格候选少于 20 时阻塞；股票定额器检查每个目标最低 100 股与单券上限。 | 共享内核应保留该能力而非只依赖调用入口。 |
| 两账户 Top 20 容量冲突 | 已覆盖 | 共同定额内核要求恰为 20 个候选；股票、转债入口和资金调拨层均以容量冲突失败关闭，不再使用转债安全阀降级。 | 最低交易单位可承载性仍须由账户定额器在冻结报价下判定。 |
| 离散单位与不透支 | 已覆盖 | 股票使用 100 股、转债使用 10 张；股票风险减仓同样固定为 100 股整数倍；股票模型金额按厘整数化，并在求解与结果复核中使用同一笔正式取整费用。 | 实际成交费用和滑点仍属于执行日事实。 |
| 取整后的余现使用 | 已覆盖 | 两个账户都只在等权最优集合内继续最小化余现；若额外买入会恶化平方等权误差，则保留现金并归因为 `equal_weight_priority`。 | 页面尚未展示余现归因。 |
| 卖出权限不被资金目标放宽 | 已覆盖 | 股票只允许冻结的退出与风险减仓；转债只在策略已授权的正常等权调仓范围内减仓。权限作为共享求解器输入，不能由余现或费用目标临时改变。 | 必要卖出原因的逐笔展示仍不完整。 |
| 费用预留进入现金约束 | 已覆盖 | 股票按必要卖出和买入订单数精确确定正式取整费用；转债采用 `max(10 元, 总成交额 × 0.01%)`。候选比较和计划现金摘要均扣除该费用。 | 费用只作粗略预留，不替代实际成交费用。 |
| 统一单标的风险防线 | 已覆盖 | 两策略均按扣除候选费用前、已冻结的策略可执行预算使用 10% 上限；股票求解摘要额外输出 `risk_cap_basis` 与 `risk_cap_value`。 | 计划展示仍需补每只标的的上限校验与计划后权重证据。 |
| 执行日价格与资格护栏 | 部分覆盖 | 计划展示层为转债买入提供低于 130 元的执行护栏；规则规定执行日跳过、缩减而不替补。 | 需要把护栏、原计划买入优先级和余额原因纳入统一输出证据。 |
| 计划后权重、余现原因和摩擦说明 | 缺失 | 当前账户计划提供期初现金、调拨、预计买卖与计划后现金。 | 未输出所有标的计划后权重、理论等权、费用、自然余现原因或组合级取舍依据。 |
| 组合级唯一解 | 已覆盖 | 两个账户共用分层 MILP，逐层固定平方跟踪误差、最大偏离、总绝对偏离、余现、费用和订单数，再逐标的锁定最终平局；均输出 `OPTIMAL`、MIP gap 和分层求解证据。 | 页面尚未展示求解证据。 |

## 3. 直接证据

- [共享等权 MILP](../../strategies/equal_weight_milp.py) 统一实施离散目标态、字典序组合质量、费用、现金、集中度与确定性平局；[共同费用与接口](../../strategies/discrete_target_sizing.py) 定义股票和转债费用适配。
- [股票适配器](../../strategies/stock_smallcap/target_sizing.py) 负责冻结普通卖出边界、100 股单位、普通订单门槛及订单字段；兼容入口不再持有独立求解算法。
- [转债定额器](../../strategies/cb_rotation/size_orders.py) 使用同一共享 MILP，传入 10 张单位、正常等权减仓权限和组合级最低费用计划。
- [订单定额编排](../../app/order_sizing.py) 与 [现金汇总](../../app/plan_service.py) 将内核估算费用带入计划后现金；执行读模型和页面的逐笔费用展示仍待补充。
- [计划执行读模型](../../app/plan_execution_read_model.py) 正确展示了“期初 + 调拨 + 卖出 − 买入”的账户现金方程，但该方程同样不含费用与计划后权重。
- [股票历史只读冒烟回放](../../scripts/replay_stock_sizing.py) 从已生成计划的冻结输入重算目标，并检查求解器状态、现金非负、卖出授权、风险减仓整手和确定性；它不是独立最优性证明，默认输出不包含持仓、价格或金额。独立最优性由 2 至 5 只股票、跨买入订单数的精确穷举 oracle 覆盖。

## 4. 改造前必须保留的行为

1. 资金调拨计划前置；订单定额只能消费执行日可用资金，不能为了订单回推或等待未来调拨。
2. 卖出阶段先于买入阶段；未实际获得的资金不得支持人工继续买入。
3. 计划只指导下一个交易日，盘中不重算、不更换榜单外标的；执行差异进入下一次真实账户事实。
4. 容量冲突、冻结、费用、不可交易和不足下一手必须与普通可投资余现分开说明。
