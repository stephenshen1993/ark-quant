## 3. 总体结论

当前工具主链路已经对齐 v2026-08 的核心结构：A/B/C 顶层目标、A 组合内部目标、A 内部父子展示、现金池共享即时现金上限、B 申购受限处理、现有账户内目标态订单和旧计划失效边界均已有实现或测试锚点。账户内交易定额已更新为共同 Top 20、10% 风险防线与全局离散比较规则，现有代码仍存在待替换差距。

后续工程不应再从“主动组合、广发、华泰、资金账户并列”或“旧国内四块目标”出发。主要剩余差距集中在四类：

- B 多承载通道、数据源稳定性、真实执行状态等实现限制。
- 历史 `strategy` 命名和个别文档仍带来的口径噪声。
- 形成期阈值、粗略费用、首次完整季度迁移等需要真实计划记录验证的测试缺口。
- 页面一键编排、结果卡、计算依据展开等 UI 便利行为需要继续保持“展示工具”边界。

## 5. 后续工程候选

优先级最高的后续工程候选：

1. B 多承载通道汇总：让账户事实从单一海外长钱承载扩展为 B 组合聚合。
2. C 执行约束回归测试：覆盖 C 申购、赎回、1% 台阶和调后状态文案。
3. `strategy` 历史命名清理：把 API、账户事实和页面模型中的策略/账户/组合边界进一步显式化。
4. 可转债数据源稳定性：关键字段快照、缓存最大有效期、第二供应方和差异报告。
5. 温度换源台账：用人工记录模板承接低频来源治理，而不是自动多源投票。

适合进入验证记录而不是代码改造的事项：

- 形成期阈值、费用预留、取整和资金链的真实计划复盘。
- 小市值果仁字段语义抽样核对。
- 可转债 DIY V0 的周频回测和实盘有效性复盘。
- 首次顶层完整季度迁移的人工验收记录。

当前明确暂缓，不作为本轮工程范围：

- 自动下单、自动申赎或自动执行多账户动作。
- 成交回报、部分成交、费用、滑点和失败回滚状态机。
- 投资账本、MWR/TWR、生活现金流、生产力支出和长期绩效平台迁移。
