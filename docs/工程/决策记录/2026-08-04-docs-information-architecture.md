# 文档信息架构整理记录

> 状态：工程决策记录
> 职责：记录 2026-08-04 文档目录整理的目标、边界和迁移规则。
> 真源范围：本次文档整理的原则与路径归属。
> 不负责：定义投资规则、策略参数或工程实现。
> 最后核对：2026-08-04

## 背景

`docs/` 已同时承载当前规则、研究过程、证据附件、历史方案和 agent 执行计划。策略目录中大量 CSV/JSON 证据冲淡了日常入口，`docs/superpowers/`、`docs/工程记录/`、`docs/操作/` 和 `docs/看板/` 也让顶层目录职责变得模糊。

## 决策

采用“少目录、强入口”的文档结构。顶层只保留日常心智清楚的目录：`体系/`、`策略/`、`工程/`、`使用/`、`研究/`、`复盘/` 和 `档案/`。

路径迁移规则：

- `docs/策略/` 根目录只保留当前策略规则、验证记录、研究看板和目录索引。
- 可转债因子总账、阶段结论、对抗审查、目标草案、前瞻影子清单和可转债证据附件统一放入 `docs/策略/可转债研究/`。
- 小市值策略的取证、回测和配置附件统一放入 `docs/策略/小市值研究/`。
- 已结束的 agent plans/specs 从 `docs/superpowers/` 并入 `docs/工程/历史设计/方案/` 和 `docs/工程/历史设计/规格/`。
- 不保留旧路径跳转文件，直接更新仓库内引用。
- 历史档案中关于旧目录的描述保持原貌，用于追溯当时结构。

## 后续维护

新增当前规则优先写入 `体系/` 或 `策略/`。新增研究过程和证据先进入对应研究子目录，只有经复核并写入当前规则后才成为执行规则。新增工程方案或规格在完成、暂停或废弃后归入 `工程/历史设计/`。
