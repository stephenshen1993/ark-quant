# 04 迁移收口与回归验收

> 状态：已完成（2026-08-08）
> 前置：03 账户总览与单账户编辑界面
> 后续：无

## 目标

确认新模型不丢失旧账户数据、不破坏计划生成，并把新的账户交互纳入自动化与视觉回归闸门。

## 范围

- 对现有账户金额和持仓历史执行只读迁移核对。
- 验证每个账户迁移前后当前值、数据时间和持仓数量一致。
- 验证后录入旧日期不会改变当前值。
- 更新旧页面测试，删除只验证全局事实日/roll-forward/批量保存的过时断言。
- 增加当前账户 module、HTTP、页面交互和计划 readiness 的行为测试。
- 扩充 UI smoke：账户总览、证券账户无修改/有修改/空仓/行情缺失/冲突、金额账户零值确认。
- 更新账户使用说明与视觉回归文档。
- 删除生产调用链中不再使用的前端批量保存逻辑；旧后端兼容端点暂保留。

## 不做

- 不删除历史账户记录。
- 不把 throwaway 原型并入生产 bundle。
- 不顺带改计划页或更新日志视觉结构。

## 验收

- `.venv/bin/python -m unittest discover -s tests -v` 全通过。
- `.venv/bin/ruff check .` 全通过。
- UI smoke 的 wide、desktop、narrow 全通过。
- 人工视觉核对确认桌面与 `390px` 的账户总览和单账户编辑无溢出、无伪零值、无全局事实日入口。
- 迁移核对报告明确记录数据数量与异常；任何不一致都必须在合并前解释或修复。

## 验收记录

- 全量单元测试：340 项通过。
- Ruff：通过。
- UI smoke：wide、desktop、narrow 均通过；无横向溢出、裁切、控制台错误或页面错误。
- 高风险交互：清空最后一笔持仓的请求保留证券账户现金；冲突保留草稿并提供重载入口；readiness 失败时五个账户均为待确认，重试后恢复。
- 数据一致性：缺失账户 backfill 不创建当前状态或 operational snapshot；新旧接口并发首次激活只允许一种模型写入。
- 迁移核对：见 [迁移核对报告](迁移核对报告.md)。
