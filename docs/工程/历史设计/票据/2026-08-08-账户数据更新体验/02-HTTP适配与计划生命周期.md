# 02 HTTP adapter 与计划生命周期

> 状态：已完成（2026-08-08）
> 前置：01 当前账户状态 module 与持久化
> 后续：03 单账户编辑界面

## 目标

让页面通过小型逐账户 interface 读取和提交当前数据，并把实际变化、无变化确认、行情缺失和并发冲突正确映射到计划生命周期。

## 范围

- 增加账户当前状态列表、单账户读取、普通更新和确认端点。
- 普通证券账户请求只接受版本、可用现金、冻结现金、证券代码与数量。
- 金额账户请求只接受版本与金额。
- 服务器自动记录正常更新的数据时间。
- 实际变化清除旧派生订单并标记当前计划失效。
- 无变化确认刷新账户时间，但不清除订单、不使计划失效。
- 冲突返回 `409` 与最新状态摘要。
- 行情失败不阻塞原始数据保存，计划 readiness 明确报告估值阻塞。
- 旧 summary/snapshot/state 端点保留读取兼容，但退出账户主页面调用链；账户形成新模型版本后拒绝旧写入，兼容资格检查与写入处于同一串行事务，避免并发双真相。
- 生成中的计划也会在账户变化时进入 `stale`；完成写入使用状态比较，晚到结果不能覆盖失效状态。

## 不做

- 不实现页面结构。
- 不移除旧端点或历史表。

## 验收

- API 测试覆盖五类账户、实际变化、确认不变、空仓、零金额、行情失败和冲突。
- 请求模型拒绝额外字段，不接受用户提交的证券名称、总资产或正常更新日期。
- 账户页与计划页消费同一计划 readiness interface，并与逐账户当前状态合并展示。
- readiness 失败时账户页 fail closed，将五个账户标为待确认并提供重试，不误报已就绪。
- 实际变化与确认不变对计划生命周期的影响不同且可验证。
