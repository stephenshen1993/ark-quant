`account_state_versions` 为 0 表示现有本地数据仍通过 legacy 基线读取；新模型会在用户首次逐账户更新或确认时为该账户建立显式版本，不要求一次性重写全部历史。

## 一致性结果

- 在数据库副本上重复执行迁移后，以上四张表的有序行指纹均保持一致，未新增、删除或改写历史账户数据。
- 五个账户均可通过当前账户状态 module 读取。
- 广发账户与华泰账户的最新账户金额日期和最新持仓日期不存在错配。
- 未发现需要人工解释的数据数量异常。

## 已加固边界

- legacy 证券数据只组合相同业务日期的现金与持仓；任一侧缺失时标记为待更新，不伪装成已确认空仓。
- 历史补录必须早于该账户当前数据日期，未来日期补录被拒绝；缺失账户的补录也只写历史版本，不物化为当前 operational snapshot。
- 某账户形成新模型版本后，旧 snapshot/state 写端点返回 `409`；资格检查与 legacy 写入在同一串行事务中，并发首次激活也不会形成两套当前值。
- 账户更新会同时使 `running` 与 `complete` 计划失效；计划完成写入只能从 `running` 状态成功，不能复活已失效计划。
