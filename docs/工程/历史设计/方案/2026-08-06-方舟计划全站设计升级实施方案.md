## 执行原则

- 按 T01 → T07 顺序实施。T03—T06 都会修改 `app/static/index.html`，不得并行施工。
- 每票先写或调整失败测试，再实现最小生产改动，再运行聚焦测试。
- 不在任何票据中修改投资规则、再平衡公式、策略算法或交易日判断。
- 原型只用于视觉对照，禁止复制夹具金额、日期、证券和原型控制器。
- T07 前允许旧视觉闸门因布局基准变化暂时失败，但相关行为测试必须保持通过；T07 必须完成三视口收口。

## T01：计划事实就绪度 interface

### 目标

让账户页和计划页通过同一服务端 interface 获得当前计划基准日、输入窗口、整体就绪度与五账户逐项状态，前端不比较日期、不维护必备账户集合。

### 文件

- Modify: `app/plan_service.py`
- Modify: `app/routers/plans.py`
- Modify: `tests/test_api_plans.py`

### 测试先行

新增或调整测试覆盖：

- 五账户均在窗口内返回 `ready`；
- 单账户缺失返回 `missing`；
- 单账户窗口外返回 `outside_window`；
- 海外账户窗口外参与完整计划阻断；
- 无账户快照仍返回五账户状态和结构化错误；
- 周一盘前接受周五计划事实的既有业务日行为；
- `GET /api/plan/readiness` 对业务缺事实返回 `200`，不返回 `409`。

### 实现要求

- 增加 `build_plan_readiness()`，内部复用 `validate_account_inputs(..., include_overseas=True)`。
- 逐账户显示信息复用账户 read-model 的顺序、名称和组合归属，不建立第二套展示命名。
- 路由只做 HTTP adapter，不复制判断。

### 验证

```bash
.venv/bin/python -m unittest tests.test_api_plans -v
```

### 完成条件

- 响应结构与规格第 5.2 节一致。
- 前端尚未接入时，现有 `/api/plan` 行为和测试不变。

## T02：最新生成生命周期 interface

### 目标

允许页面刷新后恢复当前计划基准日最新生成记录的 `running`、`complete`、`failed`、`stale` 元数据，不凭日期或本地状态猜测。

### 文件

- Modify: `datasource/db.py`
- Modify: `app/plan_lifecycle.py`
- Modify: `app/routers/plans.py`
- Modify: `tests/test_plan_lifecycle.py`
- Modify: `tests/test_api_plans.py`

### 测试先行

覆盖：

- 当前计划日无记录返回 `generation: null`；
- 同计划日多条记录按 `created_at` 和稳定次序取最新；
- 不读取其他计划日记录；
- 账户事实变化后最新 `complete` 可读为 `stale` 并带 reason；
- 最新失败记录返回 stage/code/message；
- `GET /api/plan/generated` 不返回旧计划动作或完整 `plan_json`。

### 实现要求

- datasource adapter 只负责 SQLite 查询和 JSON error 反序列化。
- `plan_lifecycle.get_latest_plan_status()` 负责默认计划日期与公开投影。
- 路由无记录时返回 `200`，不是 `404`。

### 验证

```bash
.venv/bin/python -m unittest tests.test_plan_lifecycle tests.test_api_plans -v
```

### 完成条件

- 现有按 `plan_id` 读取 interface 保持兼容。
- lifecycle 元数据与当前预览计划保持概念分离。

## T04：今日计划五状态与行动摘要

### 目标

把计划页改为任务优先状态页：先给今日结论与行动摘要，再给就绪度、偏离、资金边界、调拨、订单和计算依据。

### 依赖

- T01、T02、T03

### 文件

- Modify: `app/static/index.html`
- Modify: `tests/test_trading_page.py`
- Modify: `tests/test_api_plans.py`（仅在前端所需结构化契约缺少断言时）

### 测试先行

覆盖：

- 待补充事实、正在生成、今日无需操作、今日需要操作、计划失效、计划失败；
- 具体动作紧接今日结论，早于就绪度和计算依据；
- `sell → same_day transfer → buy → next_trading_day/deferred follow-up`；
- 次日回流不显示为今日买入预算；
- 无动作显示完整结论、计划日期和依据；
- `stale/failed` 不展示旧动作；
- 生成请求 pending 使用不确定进度和 `aria-busy`，不伪造后端阶段；
- 只有一个常规主动作“生成完整计划”。

### 实现要求

- 行动归一化只读 `execution_sequence`、`fund_transfer`、`available_on`、`cash_effect` 和结构化订单。
- 不解析 `transfer_steps` 中文文本决定顺序或状态。
- 配置偏离只使用紧凑水平对比条并同时显示精确数值。
- 计算依据就近渐进展开；保留现有计划条件与高级操作，但降低层级。

### 验证

```bash
.venv/bin/python -m unittest tests.test_trading_page tests.test_api_plans -v
```

### 完成条件

- 用户不展开依据即可复述执行顺序。
- 所有既有计划生成与保存测试继续通过。

### 测试先行
