# 可审计完整计划整改设计

> 状态：已批准；来源为 2026-07-22 资金调拨结果对抗审查及用户确认。
>
> 本文补充并修正 [完整计划页面交互设计](2026-07-22-plan-page-interaction-design.md)。若两者冲突，以本文为准。

## 1. 目标

修复完整计划将“未检查或未计算”误报为“无需资金调拨”的缺陷，使资金调拨、策略预算和账户内订单使用同一份可审计决策结果。

页面采用“结论优先、过程可展开”的渐进式审计设计。用户无需理解内部检查类型即可生成常规计划，但能够追溯每项结论使用了哪些事实、目标、阈值和资金约束。

平台仍只生成计划，不执行转账、申赎或证券交易，不保存跨计划待办或自动续接状态。

## 2. 已确认根因

当前实现同时存在三项缺陷：

1. 完整计划默认不请求 A 内部调拨计算，导致已经取得榜单后仍返回 `a_internal.status = not_requested`。
2. A 内部规划器只计算目标和缺口，始终返回空的 `immediate_actions`；兼容层也没有把 A 内部净调拨写入策略预算。
3. 页面仅用 `transfer_steps.length` 判断状态，把未检查、暂停、受限和真正无动作全部显示为“已检查，无需资金调拨”。

此外，一键生成按“转债榜单 -> 转债订单 -> 股票榜单 -> 股票订单”串行处理，而订单前置校验要求两份榜单同时存在，造成首个策略被第二个尚未生成的榜单错误阻断。

## 3. 设计原则

- 资金调拨规则只在后端纯计算模块实现；前端只展示结构化结果，不复制投资公式。
- 顶层 A/B/C 和 A 内部是两个检查层级，必须分别表达检查范围、判断结果和动作。
- 目标缺口、通过阈值的计划动作、当前立即可执行动作是三种不同含义，不能合并。
- 账户间调拨与账户内榜单保持职责独立；完整计划只在最后把已经成立的调拨预算与榜单、持仓合并。
- 所有资金动作使用以现金池为中心的星型关系，不生成策略之间的直接调拨。
- 当前真实可用现金、尚需卖出释放的资金和未到账资金必须分开；未到账资金不得进入当前可执行订单预算。
- 没有证据时显示“不知道、未检查或暂停”，不得推断“无需动作”。

## 4. 完整计划生成顺序

一键生成改为以下阶段：

1. 保存本次真实事实和特殊事项；默认是 A 内部常态检查。
2. 同时补齐转债和股票两份同日榜单；两个榜单阶段结束后再进入下一步。
3. 使用账户事实、温度、触发范围、B 核验事实和转债有效候选数，计算顶层与 A 内部资金调拨。
4. 校验两层计划共享的当前真实现金上限，得到每个策略本次可执行预算。
5. 根据对应榜单、持仓和可执行预算分别生成转债与股票订单。
6. 汇总决策轨迹、资金动作、策略预算、订单和局部错误。

共同输入错误在第三阶段阻断后续计算。榜单或订单的局部数据源错误分别记录，但不得用另一策略尚未完成的中间状态误报日期冲突。

## 5. 资金调拨计算

### 5.1 顶层 A/B/C

始终计算并返回当前比例、动态目标、完整缺口和外侧允许范围，但只按本次触发范围形成动作：

- A 内部常态检查：顶层状态为 `not_requested`，保留偏离证据，不生成顶层动作。
- 月度新增本金：只使用真实新增本金和当前可用现金修复低配，不卖老仓。
- 季度或临时顶层检查：只有严格越过外侧线才按半带宽形成老仓调整。
- B 申购事实未核验或受限：保留理想缺口，分别展示受限后的部分可执行方案和阻断原因。

首次迁移期仍由人的触发权控制。默认常规按钮不能把 A 内部检查暗中升级为季度顶层检查。

### 5.2 A 内部

当同日转债榜单可用时，按 `A_exec` 计算股票、转债和现金最终目标；转债有效候选不足时，安全阀差额进入现金目标。

对股票和转债分别计算：

```text
完整净调整缺口 = 最终目标金额 - 当前策略金额
```

只有绝对缺口达到 `1000 元`才进入动作检查。现金池不单独应用阈值，作为结算对手方和最终余项。

进入动作检查后，结果必须区分：

- `ideal_delta`：不考虑执行约束的完整净缺口；
- `planned_delta`：通过阈值、去向可形成合规订单且满足收支守恒的计划调整；
- `immediate_delta`：由当前真实可用现金支持、现在可以先执行的部分；
- `deferred_gap`：尚需卖出、转账或到账后重新计算的差额，仅作解释，不保存为待办。

高配策略通过其承载通道调出到现金池，低配策略由现金池调入。当前现金可以在共享上限内桥接低配动作；尚未卖出或未到账金额不能重复算作当前购买力。

### 5.3 策略预算与订单

每个策略订单必须显示并使用：

```text
本次可执行策略预算
= 当前策略资产金额
+ 本次由当前真实现金支持的调入
- 本次计划调出
```

来源策略的计划调出需要在账户内订单中形成足够的净卖出；去向策略的买单不得超过已经由当前真实现金支持的调入和该账户原有可用现金。需要等待外部到账的部分不进入本次买单。

## 6. 决策轨迹数据结构

完整计划响应新增结构化 `decision_trace`，只随本次响应实时生成，不新增数据库状态：

- `scope`：本次触发事实、顶层是否纳入、A 内部是否纳入；
- `inputs`：计划日、适用交易日、温度及来源、账户更新时间、B 核验事实、榜单状态和候选数；
- `top_level`：当前、目标、允许范围、偏离、阈值判断、理想与可执行动作；
- `a_internal`：当前、目标、缺口、`1000 元`阈值、安全阀和动作；
- `cash_constraints`：真实现金、已占用现金、计划来源、立即可执行额和未到账差额；
- `strategy_budgets`：股票与转债的当前资产、调拨增减、本次预算；
- `stages`：榜单、资金调拨、订单生成各阶段状态及错误。

金额和比例字段保留机器可读数值，同时提供稳定的状态码和中文原因；前端不从文案反推业务状态。

## 7. 状态语义

每个检查层级只允许以下状态：

- `not_requested`：本次未启动该层检查；
- `waiting_for_evidence`：缺榜单、B 核验或其他必要事实；
- `within_threshold`：已完整检查，所有有效缺口均未达到动作阈值；
- `action_required`：存在通过阈值的计划动作；
- `constrained`：存在理想动作，但受真实现金、申购或最小订单约束；
- `ready`：动作和策略预算均已形成；
- `failed`：计算或数据源失败。

只有 `within_threshold` 且审计字段完整时，页面才可以出现“已检查，本次无需调拨”。

## 8. 页面信息架构

常规页面继续只有一个主按钮“生成完整计划”。内部检查类型不再作为默认下拉框暴露；低频特殊事项放在“本次有特殊情况”折叠区，由事实自动映射触发类型。

生成结果按以下顺序展示：

1. **本次检查范围**：A 内部是否检查，顶层 A/B/C 是否检查及原因。
2. **结论摘要**：需要调拨、阈值内、受限、暂停或失败，不使用模糊绿色成功状态。
3. **资金调拨动作**：按来源、现金池和去向展示金额、当前可执行性与原因。
4. **策略预算与订单**：每个账户内计划显示预算来源和调拨影响。
5. **决策依据**：默认折叠，展开后显示顶层表、A 内部表、现金约束和生成阶段。

顶层表和 A 内部表每行至少显示：当前值、目标值、完整缺口、阈值或允许范围、判断、计划动作、限制原因。颜色不能是唯一状态表达，所有状态必须有文字。

## 9. 错误处理

- 账户事实日期错误：显示具体账户、实际更新时间和允许窗口。
- 榜单缺失：指明策略与计划日；补齐两份榜单后再开始订单阶段。
- A 内部缺少转债候选数：显示“等待同日转债榜单，安全阀无法确认”，不得显示无需调拨。
- B 未核验：顶层理想偏离照常展示，但申购动作标记受限。
- 局部订单失败：保留已完成的决策轨迹和另一策略结果，明确完整计划尚未全部就绪。
- 页面刷新：重新读取事实和计划，不把旧的临时错误或成功状态当作当前结论。

## 10. 验收标准

- 当前温度和账户事实下，A 内部股票、转债缺口超过 `1000 元`时，不再显示“无需调拨”。
- A 内部常态检查明确显示“顶层本次未启动”，季度检查才应用顶层硬偏离规则。
- 缺榜单、候选数不足、B 未核验和真实阈值内分别显示不同状态。
- 一键生成先完成两份榜单，再计算调拨和订单，不再出现转债先被股票榜单缺失阻断的顺序缺陷。
- 完整计划中的 `transfer_deltas`、策略预算、订单现金约束和决策轨迹相互一致。
- A 内部调拨遵守 `1000 元`阈值、星型关系、共享现金上限和转债候选安全阀。
- 未到账资金不进入当前订单预算；立即调拨金额不超过真实可用现金。
- 页面能从结论逐层展开到输入、目标、偏离、阈值、限制和动作，无需查看源码即可解释结果。
- 全量自动化测试、JavaScript 语法检查和浏览器桌面宽度验收通过。

## 11. 不在本次范围

- 修改投资体系的目标比例、阈值或首次迁移规则；
- 自动判断季度到期或自动触发临时检查；
- 自动转账、申赎、下单、成交回写或跨日任务续跑；
- 新增长期审计数据库、绩效账本或历史计划执行状态；
- 修改股票或可转债账户内选标的和排序规则。
