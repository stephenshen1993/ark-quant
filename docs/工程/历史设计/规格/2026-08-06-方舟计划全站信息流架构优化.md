# 方舟计划全站信息流架构优化规格

> 状态：待实施
> 职责：定义全站信息流重排后的导航语义、跨页状态、页面首屏结构和验收标准。
> 真源范围：Web 工作台的信息架构、页面阅读顺序、用户可见命名和原型选型结论。
> 不负责：修改投资规则、账户事实口径、资金调拨算法、订单 sizing 算法、成交状态或自动交易。
> 最后核对：2026-08-06

## 1. 来源与结论

本规格来自：

- `CONTEXT.md` 的 Web 产品体验词汇。
- `/private/tmp/ark-quant-information-flow-prototype-handoff-2026-08-06.md`。
- 可丢弃原型 `app/static/information-flow-prototype.html`。
- 截图证据 `outputs/prototype-information-flow/`。

结论：采用原型 A「状态主线」作为规格基线，吸收原型 B「执行时间线」里的异常插队和执行依赖表达，不采用原型 C「分栏控制台」的控制台布局。

## 2. 目标

升级后的全站第一眼必须回答：

1. 系统当前处于哪个投资工作状态。
2. 当前状态由哪些事实、判断和执行条件构成。
3. 是否存在阻塞；如果有，先去哪里修复。
4. 若计划可执行，应先看资金调拨计划，再看账户交易计划。

这次优化把页面从“今天有没有操作”上移到“当前投资工作状态”。“今日无需操作”和“今日需要操作”仍是重要结论，但不是全站信息流唯一中心。

## 3. 范围

### 3.1 包含

- 导航与默认入口从“今日计划”调整为“今日状态”。
- 保留三个轻量主入口：今日状态、账户事实、更新日志。
- 新增或重排全局状态条，跨页展示计划基准日、输入窗口、生成状态和阻塞摘要。
- 今日状态首屏采用“单一总判断 + 状态链”。
- 今日状态内容顺序调整为资金调拨计划先于账户交易计划。
- 异常状态下，阻塞说明和修复入口插队到总判断下方。
- 账户事实页首屏采用“事实就绪度 -> 资产结构”两层。
- 更新日志保留连续阅读，并增加轻量影响范围标签。
- 全站稳定区分事实、判断、执行三类信息。
- 桌面和 `390px` 手机视觉验收。

### 3.2 不包含

- 不新增独立仪表盘。
- 不把更新日志改成审计后台、issue 列表或功能矩阵。
- 不在全站首屏展示总资产、主动组合金额或资金余额资产总览。
- 不改变资金调拨计划、账户交易计划、证券交易明细的领域含义。
- 不改变计划生成、资金调拨和订单 sizing 的计算逻辑。
- 不实现自动下单、自动调拨或成交回写。
- 不把 prototype switcher 或 losing variants 合入生产。

## 4. 命名与导航

生产导航顺序：

1. 今日状态
2. 账户事实
3. 更新日志

约束：

- 默认入口为今日状态。
- URL hash 应从 `#trading` 迁移或兼容到 `#today`。为了不破坏已有链接，`#trading` 应继续重定向或映射到今日状态。
- 页面内部仍保留“资金调拨计划”“账户交易计划”等领域对象名称。
- 页面标题、导航、关键区块标题优先使用中文承载语义；英文眉题仅作轻量视觉节奏。
- 左侧导航不扩展成多级后台菜单。

## 5. 全局状态条

全局状态条出现在三个主入口的内容顶部，承担共享仪表读数，不替代页面标题。

必须表达：

- 计划基准日。
- 输入窗口或适用执行窗口。
- 账户事实状态。
- 资金调拨状态。
- 计划生成生命周期状态。
- 是否存在阻塞。

状态条行为：

- 桌面使用一行紧凑结构；空间不足时允许换行。
- 手机使用竖向堆叠，确保每个状态标签完整显示。
- 状态条不显示资产总览。
- 状态条不把旧计划动作伪装成当前建议。
- 数据缺失时显示明确的待确认或无法确认状态，不用空白占位。

## 6. 今日状态入口

### 6.1 首屏结构

今日状态首屏顺序：

1. 页面标题“今日状态”和简短说明。
2. 单一总判断。
3. 生成或重新生成计划的工具动作。
4. 状态链。

总判断覆盖五类用户工作状态：

- 待补充事实。
- 正在生成。
- 今日无需操作。
- 今日需要操作。
- 计划已失效或失败。

状态链至少表达：

- 账户事实。
- 资金调拨。
- 账户交易计划。
- 执行窗口。

### 6.2 内容顺序

正常可执行或无需操作时，今日状态内容顺序为：

1. 资金调拨计划。
2. 账户交易计划。
3. 本次计划条件或计算依据。
4. 高级操作。

异常时，阻塞说明和修复入口插队到总判断下方，优先于正常计划内容。

### 6.3 计划生成动作

- 未生成、失效或失败时，生成按钮可强化。
- 已有完整计划时，重新生成计划退为次级工具按钮。
- 按钮文案不得暗示已经下单、成交或自动执行。

### 6.4 资金与交易关系

- 资金调拨动作只出现在资金调拨计划内。
- 证券交易明细只出现在所属账户交易计划内。
- 不出现全局扁平买卖列表。
- 不用全局交易笔数或步骤数表达工作量。
- 账户交易计划按资金已具备、需要当日调入、等待未来资金可用排序。

## 7. 账户事实入口

账户事实入口首屏顺序：

1. 账户事实就绪度。
2. 待维护事项汇总，仅在缺失或过期时突出。
3. A/B/C 组合、主动组合、广发账户、华泰账户和资金账户的资产结构。
4. 每个账户自己的维护入口。

约束：

- 账户事实页不是单纯资产看板，也不是只含维护任务的清单。
- 事实就绪度来自服务端计划输入窗口判断，不在前端自定义过期阈值。
- 资金账户内金额事实称为“资金余额”。
- 预计资金余额不得表现成真实账户余额。

## 8. 更新日志入口

更新日志保持连续阅读形态。

可新增轻量影响范围标签：

- 今日状态。
- 账户事实。
- 计划生成。
- 视觉系统。
- 其他后续明确的工作流节点。

约束：

- 标签只服务阅读定位。
- 不新增筛选、搜索或工程审计元数据。
- 不把更新日志改成工作台卡片流、issue 列表或功能矩阵。

## 9. 视觉与响应式约束

- 继续使用浅色、克制、精密的数据感。
- 卡片圆角不超过现有 `6px` 基线。
- 不增加渐变、装饰性阴影、资产趋势图或常驻图表。
- 桌面保持中等偏高密度，首屏能同时看到总判断、状态链和资金调拨计划开头。
- `390px` 手机优先显示全局状态条、页面标题、总判断和状态链；允许下方计划内容滚动。
- 所有状态不能只靠颜色表达，必须有文本。
- 文字不得横向溢出，按钮文案不得截断到不可理解。

## 10. 验收标准

实现完成后必须通过：

- 单元测试：`.venv/bin/python -m unittest discover -s tests -v`。
- 静态检查：`.venv/bin/ruff check .`。
- UI smoke：覆盖 `wide`、`desktop`、`narrow` 三类视口。
- 视觉检查：
  - 今日状态桌面首屏能读出当前状态、阻塞和下一步。
  - 今日状态手机首屏无横向溢出。
  - 账户事实桌面首屏先表达就绪度，再表达资产结构。
  - 更新日志保持连续阅读，并能看到影响范围标签。
  - `#trading` 旧链接仍能进入今日状态。
