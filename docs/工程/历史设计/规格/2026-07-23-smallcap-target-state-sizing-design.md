# 小市值目标态定额设计

> 状态：待用户审阅
> 范围：把已确认的小市值账户内执行规则收口为唯一的定额实现；不修改选股因子、持仓数量、轮动频率或体系级资金调拨规则。

## 目标

对同一份 Top 20 榜单、真实持仓、可执行策略预算和报价，命令行与计划 API 必须产生相同的目标手数、净订单、告警和现金结果。

## 边界

- 输入预算是体系级资金调拨已经确认后的股票账户可执行预算；定额器不计算资金调拨，也不把预计卖出、赎回或未到账调拨当作现金事实。
- 只生成执行草案，不连接券商、不下单、不记录成交状态或跨日待办。
- 目标集合固定为本次 Top 20。不可因价格、容量或门槛问题替换为第 21 名。

## 共享定额器

新增一个纯函数模块，输入按排名排列的 Top 20、当前持仓、报价和可执行预算，返回：

- 每个目标标的的完整目标股数和目标金额；
- 合并后的净订单（买入、加仓、减仓、卖出、持有或暂停）；
- 普通订单门槛、剩余现金与费用预留；
- 结构化告警，包括容量冲突、报价缺失和集中度风险。

计划 API 和命令行包装层均只负责读取输入、调用该函数和保存/展示结果，不能再各自实现取整或门槛规则。

## 定额规则

设可执行策略预算为 `B`，目标数为 20，单只理论目标 `S = B / 20`。

1. 先检查每个 Top 20 的一手（100 股）成本。任一标的一手成本超过 `B × 10%` 时，返回容量冲突；若不能让 20 只各至少买入一手，也返回容量冲突。容量冲突不替换股票、不生成普通交易计划。
2. 先为每只目标按 `S` 向下取整到 100 股，且不超过 `B × 10%`；已有持仓超过上限时，目标仍回归接近 `S`。
3. 在卖出释放资金、预算和粗略费用预留允许的范围内，将剩余现金逐手补给相对目标最欠配的标的；欠配相同则排名更高者优先。每次补一手后重新比较。
4. 由完整目标态减去真实持仓，合并为每个代码一笔净订单。
5. 普通净订单的门槛为 `max(1000 元, S × 10%)`。低于门槛的普通买入、加仓、减仓本次不执行。
6. 排名退出、风险退出、清尾仓及将已有仓位从 `10%` 以上降向 `S` 的集中度减持，不适用普通订单门槛。
7. 过滤普通订单后的剩余现金只能修补仍欠配的买入方向：新的首笔修补必须达到普通门槛；已经有合格净买单的标的可继续加一手。不得为用尽现金制造普通卖单。
8. 任何买入预算均不能为负；报价缺失或无法满足容量约束时，明确停止，而非输出部分 Top 20 或以零股静默降级。

## 接口和兼容性

- `/api/plan/stock/size-orders` 继续使用现有计划日期、持仓事实窗口、实时报价检查和订单持久化接口；其订单内容改由共享定额器产生。
- `python -m strategies.stock_smallcap.size_orders` 继续支持现有文件/数据库输入，但改为调用相同共享定额器。
- 订单行继续保留现有字段（动作、代码、名称、报价、当前/目标股数、净股数、金额、估算费用），可增加规则性告警字段；不改变数据库中现有订单的历史含义。

## 错误处理与验收

- 缺报价：停止并报告缺失代码。
- 容量冲突：停止并报告不足原因及触发的标的，不写入新订单。
- 资金不足：不透支；只有规则允许的卖出释放资金参与本次计算。
- API 与命令行：对固定输入产生完全一致的订单和摘要。

自动化测试至少覆盖：20 只最小一手容量、单股 `10%` 上限、100 股取整、动态普通门槛、必要卖出/集中度减持的豁免、余现修补、负现金防护，以及两条入口的一致性。
