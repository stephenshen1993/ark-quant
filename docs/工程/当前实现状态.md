## 2026-09-29 证券账户现金区间

完整阶段计划先在可用资金内保留账户现金，再计算证券预算；完成整手订单后统一校准资金调拨，使广发、华泰、平安的预计未扣费可用现金落在300～1,000元。冻结现金不用于预留，预留不重复计入资产或策略等权预算，不为余额新增证券订单。实际费用由预留吸收；平安费率与最低佣金不再阻塞订单。旧规则版本计划标记失效，须重新生成。

股票、转债旧费用算法仍保留供既有命令行/研究兼容，Web完整计划显式使用现金预留口径。预览历史订单不是新生成的完整计划，不替代冻结生成结果。

## 当前主链

账户事实 → 统一阶段目标与调拨预算 → 股票/转债原策略定额及平安基金订单 → 冻结完整计划 → 人工核对并在外部执行。

- `stage_allocation.py`是本阶段唯一目标及资金预算来源；旧A/B/C、温度预算和独立新钱机制不参与当前计划，旧命令行配置入口已退役。
- 平安通过既有当前账户版本模型保存持仓、共用现金和两个基金方向交易条件。原股票/转债持仓表无需迁移；新增账户不能由缺失自动推为零。
- 直接现金单次汇总；旧投顾持有余额与赎回在途分开记录；在途和未到账卖出款不支持跨账户购买力。
- 原股票、转债筛选和等权定额求解继续接收预算，未修改策略参数；基金按明确限价、整手、费率与最低费用生成订单，回池金额不超过实际整手订单扣费后可释放金额。
- 完整计划保存配置版本、输入、预算、资金动作和订单；旧配置计划显示失效，输入变更也使旧计划失效。计划日改由交易日历确定，温度只供观察。
- 概览、账户与计划使用同一阶段口径。[使用与验收说明](../使用/阶段配置使用与验收.md)记录实际入口。

## 保留的边界

2026-09-29补充：交易计划冻结价格也调用同一除息衔接函数，以计划执行窗口判断事件生效；`raw_cb`保留原始收盘价，调整后参考价用于订单数量、卖出收入、费用及现金结余估算。计划执行说明列出调整依据。历史榜单及历史行情不改写，修复后须重新生成计划，旧冻结计划不被静默覆写。

全局比例是已确认的阶段选择，没有新增择时、自动触发或自动交易。程序仍不记录真实成交、执行进度或绩效；实际变化通过账户事实维护，收益记录仍由有知有行承载。旧API字段与A/B/C读模型保留历史兼容身份，不是第二目标来源。

原股票/转债榜单与容量约束不满足时，完整计划失败关闭；基金交易条件不足时局部保留缺口。纳指工具不预设最终代码，基金报价/溢价成本与券商费用仍须真实核验。交易日历和行情等外部源仍可能失效。

单元检查与隔离浏览器覆盖预算、账户、订单、计划失效及响应式界面。没有读取实际投资数据库来代填事实或执行交易。
