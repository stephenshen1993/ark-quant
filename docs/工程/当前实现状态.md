# 当前实现状态

> 状态：当前工程事实
> 职责：汇总 ark-quant 已实现能力、已知限制和与投资体系的主要差距。
> 真源范围：2026-07-18 的代码、测试和当前运行路径。
> 不负责：把现有实现升级为正式规则，或决定尚未盘定的战术。
> 最后核对：2026-07-18

## 1. 总体判断

当前系统已经形成“当前账户事实—策略榜单—目标金额—资金调拨计划—交易计划”的基本链路，方向上接近当前 MVP。MVP 只要求快速、可靠地生成资金调拨计划和交易计划，不要求成为完整投资体系、投资账本、绩效平台或无人值守交易系统。主要短板应按这一边界判断，而不能把尚未建设执行跟踪和绩效账本本身视为 MVP 缺陷。

## 2. 已实现

| 领域 | 当前能力 |
| --- | --- |
| 账户与持仓 | 分账户价值快照、股票/转债持仓快照、历史读取、空仓语义和原子保存 |

| 数据可靠性 | SQLite 事务、完整策略运行、关键字段校验、失败时停止输出 |
| 回归验证 | 数据库、API、温度、策略过滤、订单和计划日期等自动化测试 |

## 3. 规则与实现的关系

当前代码实现了 [仓位与再平衡规则](../体系/仓位与再平衡规则.md) 中记录的形成期公式和阈值，但这些内容仍处于战术盘点中。它们是“系统当前会怎么算”的事实，不是“体系最终应该怎么算”的证据。

两条账户内策略的正式表达见：

- [小市值股票策略规则](../策略/小市值股票策略规则.md)
- [多因子可转债策略规则](../策略/多因子可转债策略规则.md)

代码与规则不一致时，以规则为目标，在专题实现差距中登记，不回写覆盖规则。

## 4. 主要差距

### 4.1 已确认战术尚未落实到当前实现

体系级战术已经确认了中性、极低和极高三个仓位锚点、分段线性映射、等权全市场温度输入、长钱 `15%` 固定目标、可转债可投资性安全阀、策略或组合间千元级净调拨门槛、弹性检查触发和人在回路的 MVP 边界。正式规则见 [仓位与再平衡规则](../体系/仓位与再平衡规则.md) 和 [交易执行规则](../体系/交易执行规则.md)。

当前代码、配置和页面仍主要执行形成期旧公式与旧阈值，因此主要问题已经从“这些战术尚未讨论”转变为“已确认规则尚未落实”。在本轮战术继续盘清静态计划中的资金前置依赖、订单资金分配、温度来源切换、海外增量临时比例和验证方法前，仍不急于局部改代码，以免反复施工。

### 4.2 计划生成仍需对齐正式战术

当前代码中的仓位公式、调拨阈值、计划顺序和订单约束仍需随正式战术共识逐项校正。MVP 是否完成，应优先检查同一组有效输入能否快速、稳定、可解释地生成正确的资金调拨计划和交易计划。

### 4.3 策略证据不足

两条策略都有当前可运行版本，但关键参数和完整历史表现仍缺少与真实约束一致的系统回测、滚动区间检查和实盘归因。可转债专题差距见 [可转债策略实现差距](实现状态/可转债策略实现差距.md)。

### 4.4 工程与平台限制

- 当前 Web、API 和 SQLite 是本地实现，不是长期底座承诺。
- 策略 Web 运行锁是进程内锁，不解决多进程并发。
- 外部数据源仍存在可用性和字段稳定性风险。
- 订单只生成计划，系统不知道真实成交、部分成交、费用和滑点；这符合当前 MVP 边界，不要求人工写回 ark-quant。
- 账户标识和部分 API 路径仍保留历史上的 `strategy` 命名，需要靠文档和模型接口避免概念混淆。

### 4.5 非 MVP 扩展

全体系外部入金、生活分红、个人生产力支出、累计盈利台阶、沪深 300 全收益基准、MWR/TWR、计划执行状态和真实成交归因均不属于当前 MVP。长期投资账本继续使用已有三年多记录的有知有行投资账本；只有 MVP 好用并出现明确新增价值后，才评估是否同步、迁移或补充其中某些能力。

## 5. 后续顺序

1. 继续从投资体系出发盘清仓位与再平衡战术。
2. 将确认后的战术落实为清晰的资金调拨计划和交易计划口径，再评估 MVP 代码改造。
3. 验证同一输入能否快速、稳定、可解释地生成计划，并改善人工执行前的准备效率。
4. 用回测和外部实盘记录验证账户内策略参数。
5. MVP 稳定好用后，再决定是否增加执行跟踪、绩效或账本等能力，以及哪些继续交给成熟平台。

在第一步完成前，不把现有公式、比例、频率或页面交互当作约束。
