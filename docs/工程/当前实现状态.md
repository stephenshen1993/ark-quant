# 当前实现状态

> 状态：当前工程事实
> 职责：汇总 ark-quant 已实现能力、已知限制和与投资体系的主要差距。
> 真源范围：2026-07-18 的代码、测试和当前运行路径。
> 不负责：把现有实现升级为正式规则，或决定尚未盘定的战术。
> 最后核对：2026-07-18

## 1. 总体判断

当前系统可以作为近期的本地记录和计划辅助台，但不是完整投资体系，更不是无人值守交易系统。它已经形成“账户事实—策略榜单—目标金额—资金调拨—订单草案”的基本链路，主要短板在战术尚未定型、绩效记录未闭环、策略验证不足和部分工程能力仍绑定本地实现。

## 2. 已实现

| 领域 | 当前能力 |

| 账户与持仓 | 分账户价值快照、股票/转债持仓快照、历史读取、空仓语义和原子保存 |

## 3. 规则与实现的关系

当前代码实现了 [仓位与再平衡规则](../体系/仓位与再平衡规则.md) 中记录的形成期公式和阈值，但这些内容仍处于战术盘点中。它们是“系统当前会怎么算”的事实，不是“体系最终应该怎么算”的证据。

两条账户内策略的正式表达见：

- [小市值股票策略规则](../策略/小市值股票策略规则.md)
- [多因子可转债策略规则](../策略/多因子可转债策略规则.md)

代码与规则不一致时，以规则为目标，在专题实现差距中登记，不回写覆盖规则。

## 4. 主要差距

### 4.1 体系级战术尚未盘透

中性目标关系、极端估值上下限、温度映射、再平衡触发方式、动作阈值、长钱目标和海外增量规则仍需逐项推演。当前实现不应在讨论完成前继续固化这些参数。

### 4.2 绩效与资金流未闭环

系统尚未正式记录全体系外部入金、生活分红、个人生产力支出、累计盈利新台阶、沪深 300 全收益基准，以及 MWR/TWR 序列。因此当前页面不能完整回答“全体系长期是否跑赢基准”。

### 4.3 策略证据不足

两条策略都有当前可运行版本，但关键参数和完整历史表现仍缺少与真实约束一致的系统回测、滚动区间检查和实盘归因。可转债专题差距见 [可转债策略实现差距](实现状态/可转债策略实现差距.md)。

### 4.4 工程与平台限制

- 当前 Web、API 和 SQLite 是本地实现，不是长期底座承诺。
- 策略 Web 运行锁是进程内锁，不解决多进程并发。
- 外部数据源仍存在可用性和字段稳定性风险。
- 订单只生成草案，系统不知道真实成交、部分成交、费用和滑点，必须人工写回。
- 账户标识和部分 API 路径仍保留历史上的 `strategy` 命名，需要靠文档和模型接口避免概念混淆。

## 5. 后续顺序

1. 继续从投资体系出发盘清仓位与再平衡战术。
2. 将确认后的战术变更形成版本记录，再评估代码改造。
3. 补齐全体系资金流、分红和基准绩效的记录设计。
4. 用回测和实盘记录验证账户内策略参数。
5. 最后再决定哪些能力继续由 ark-quant 自建，哪些交给成熟平台。

在第一步完成前，不把现有公式、比例、频率或页面交互当作约束。
