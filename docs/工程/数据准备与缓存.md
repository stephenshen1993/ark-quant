# 数据准备与缓存

> 状态：正式实现说明
> 职责：说明计划和榜单生成的数据日期、缓存身份、运行状态与故障恢复。
> 真源范围：工程实现与可观察性；不定义策略选取规则。
> 不负责：定时调度、后台预热或交易自动执行。
> 最后核对：2026-09-08

## 运行方式

系统仍是本地按需工具。启动应用不会抓取行情或基本面，也不会计算策略；只有手动生成计划或榜单时才创建一次不可变的运行任务，冻结开始时间和有效交易日。两套策略在同一次计划生成中共用该日期。

数据准备只会报告三种模式：

- `首次冷构建`：没有可证明完整的输入，按 requirements 获取并发布新 bundle。
- `增量补齐`：已有部分历史覆盖，只请求真实交易日缺口。
- `完整缓存命中`：日期、字段、证券覆盖、来源版本和内容哈希全部匹配，远程调用为零。

每次运行的日志和策略运行 API 都包含有效交易日、上次覆盖水位、缺失交易日、失效原因、复用与刷新记录数、外部调用数、批量请求数、回退证券数及各阶段实测耗时。

转债正股历史优先使用按交易日返回全市场数据的 Tushare 批量源（通过 `TUSHARE_TOKEN` 启用，`tushare` 为可选依赖）；批量源未配置、失败或覆盖不完整时，才对缺失证券执行有界 AkShare 回退。两条路径都只请求缺失交易日范围，外部调用数按实际物理请求累计。

## 缓存身份

- 原始行情按来源、来源版本、证券和交易日保存，原始收盘价与复权因子分开记录。
- 低频基本面按证券、报告期、指标口径、来源和版本保存。
- 派生因子按证券、数据日、因子名、算法版本和输入指纹保存。
- 策略榜单按策略、数据日、策略版本、配置指纹和输入指纹保存。

排名参数、持仓数量或不影响历史抓取范围的策略阈值变化，只触发本地重筛与重排，不使完整原始输入失效。转债 bundle 同时保存原始全集与预筛后的历史抓取全集；最高转债价格、最小剩余规模、最短剩余年限、强赎排除和 ST 正股排除会改变历史抓取范围，因此纳入 bundle 身份。公司行为只更新对应证券和日期的复权事实，并精准失效其下游因子和依赖榜单。

## 发布与恢复

bundle 先写入 `incomplete` 状态，字段和覆盖校验通过后才原子发布为 `complete`。相同身份的并发任务由跨进程文件锁串行化；历史事实使用复合主键幂等写入。中途失败会保留已验证记录，下次只续补剩余缺口。损坏、日期不符或无法证明覆盖的旧缓存不会命中。

完整本地输入允许在外部数据源不可用时离线生成；存在关键缺口时停止策略并报告失败来源、阶段、有效交易日及缺失证券或日期。

### 转债停牌与行情缺口

转债批量行情和单券补抓仍缺少有效交易日数据时，查询该日东方财富停复牌记录，核对停牌开始日、截止日、预计复牌日及整日停牌类型。只有明确覆盖该日的证券停牌事实才能解释缺口；行情较旧本身不是停牌证据。深市转债允许依据正股整日停牌确认同步停牌，依据为[深交所停复牌说明](https://www.szse.cn/www/investor/knowledge/t20221026_596809.html)。沪市转债不根据正股记录推断；未经确认的缺口仍会阻止生成。

已确认停牌的券从当日行情候选范围中排除，其正股若不再被其他候选依赖，也不再请求因子历史。停牌原因、日期、来源和证券映射写入运行准备信息、日志以及原始全集的 `suspension_evidence` 字段；不填造零成交或沿用旧价格充当当日行情。状态源不可用、结构异常、复牌日已到、停牌尚未开始或只发生盘中停牌时，继续保留原行情缺口错误。全部候选停牌时停止生成。

该处理不变更已有持仓，也不生成停牌证券的卖单；计划生成中缺少持仓有效价格时仍由原有完整性校验阻止输出。转债原始输入版本升级为 `cb-raw-input-v4`，旧 bundle 不跨版本复用，已验证的逐券历史仍可复用。

## 边界

本能力不增加 cron、开机自启、后台预热、常驻服务或天级自动化。跨日与跨周复用都发生在用户下一次手动生成时。
