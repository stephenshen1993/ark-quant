# 数据准备与缓存

> 状态：正式实现说明
> 职责：说明计划和榜单生成的数据日期、缓存身份、运行状态与故障恢复。
> 真源范围：工程实现与可观察性；不定义策略选取规则。
> 不负责：定时调度、后台预热或交易自动执行。
> 最后核对：2026-08-20

## 运行方式

系统仍是本地按需工具。启动应用不会抓取行情或基本面，也不会计算策略；只有手动生成计划或榜单时才创建一次不可变的运行任务，冻结开始时间和有效交易日。两套策略在同一次计划生成中共用该日期。

数据准备只会报告三种模式：

- `首次冷构建`：没有可证明完整的输入，按 requirements 获取并发布新 bundle。
- `增量补齐`：已有部分历史覆盖，只请求真实交易日缺口。
- `完整缓存命中`：日期、字段、证券覆盖、来源版本和内容哈希全部匹配，远程调用为零。

每次运行的日志和策略运行 API 都包含有效交易日、上次覆盖水位、缺失交易日、失效原因、复用与刷新记录数、外部调用数、批量请求数、回退证券数及各阶段实测耗时。

## 缓存身份

- 原始行情按来源、来源版本、证券和交易日保存，原始收盘价与复权因子分开记录。
- 低频基本面按证券、报告期、指标口径、来源和版本保存。
- 派生因子按证券、数据日、因子名、算法版本和输入指纹保存。
- 策略榜单按策略、数据日、策略版本、配置指纹和输入指纹保存。

策略阈值或持仓数量变化只触发本地重筛与重排，不使完整原始输入失效。公司行为只更新对应证券和日期的复权事实，并精准失效其下游因子和依赖榜单。

## 发布与恢复

bundle 先写入 `incomplete` 状态，字段和覆盖校验通过后才原子发布为 `complete`。相同身份的并发任务由跨进程文件锁串行化；历史事实使用复合主键幂等写入。中途失败会保留已验证记录，下次只续补剩余缺口。损坏、日期不符或无法证明覆盖的旧缓存不会命中。

完整本地输入允许在外部数据源不可用时离线生成；存在关键缺口时停止策略并报告失败来源、阶段、有效交易日及缺失证券或日期。

## 边界

本能力不增加 cron、开机自启、后台预热、常驻服务或天级自动化。跨日与跨周复用都发生在用户下一次手动生成时。
