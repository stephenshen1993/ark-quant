# 交易计划回归验收

> 状态：当前工程验收入口
> 职责：把已确认规则映射到可重复运行的检查，并规定问题复现证据。
> 真源范围：工程验证方法。
> 不负责：调整账户目标、优化目标或执行真实交易。
> 最后核对：2026-10-26

规则依据：[交易计划验收契约](../体系/交易计划验收契约.md)、[账户内交易定额规则](../体系/账户内交易定额规则.md)和[仓位与再平衡规则](../体系/仓位与再平衡规则.md)。最大整体偏离优先是当前已确认的策略偏好；修改它须有独立的规则讨论与验收，不能由单次现金余额触发。

## 持续守住的不变量

| 检查 | 现有回归覆盖 | 判定 |
| --- | --- | --- |
| 事实可信 | `tests/test_plan_valuation.py` | 估值不改写原始事实；已扣账在途只计一次；冻结现金不进入购买力。 |
| 计算同源 | `tests/test_plan_generation.py`、`tests/test_plan_valuation.py` | 同一原始事实和冻结价得到相同估值、目标与调拨；实时价格变化不影响计划；缺价或日期不符停止生成。 |
| 资金守恒 | `tests/test_stage_allocation.py`、`tests/test_portfolio_rebalance.py`、`tests/test_api_plans.py` | 目标金额闭合；调拨不花未到账资金；账户现金留在所属账户；预览与完整计划预算一致。 |
| 持仓与现金共同优化 | `tests/test_discrete_target_sizing.py`、`tests/test_stock_sizing_replay.py` | 股票与转债采用同一比较顺序；手数、费用与集中度满足约束；冻结输入可回放。 |

在仓库根目录运行完整回归：

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/ruff check .
git diff --check
```

这些测试使用隔离事实，不需要生成新的真实账户计划。测试通过证明实现满足已覆盖场景，不代表策略收益或未来成交得到保证。

## 每份实际计划的复核

沿用计划已经冻结的输入，不以当前实时行情重算旧计划。核对计划身份、规则版本、参考价日期及原始事实版本，再依次复算账户估值、调拨和账户内现金方程。账户目标偏差须能归因到小额免调、在途或可用资金约束；持仓偏差须能归因到正式比较顺序和交易单位。

剔除计划转出、冻结和费用预留后的可投资余现超过1,000元时，检查是否存在符合全部约束、且在正式字典序下更优的组合，并记录未继续买入的原因。余额阈值本身不触发回池、减少配置调入或修改求解目标。

## 发现反例后的最小处理

记录计划 ID、规则版本、冻结输入与日期、预期不变量、实际复算差额。若质疑优化结果，须提供相同预算和约束下的替代整数持仓及字典序比较；仅比较余额大小不足以判错。涉及个人账户金额的证据保留在本地任务目录，不提交到仓库。

先区分事实变化、估值口径、预算闭合或优化实现问题，再修复对应层。可复现反例应加入原有测试模块；已有覆盖充足时不另建检查框架。按需复核新计划，不因此新增定时任务或自动交易。
