# 数据与接口口径

> 状态：当前工程事实
> 职责：把业务记录语义映射到当前 SQLite 数据组和 HTTP API。
> 真源范围：2026-07-18 的本地数据与接口实现。
> 不负责：定义账户、策略、绩效或仓位规则；这些以体系文档为准。
> 最后核对：2026-07-18

## 1. 分层原则

[投资记录与绩效口径](../体系/投资记录与绩效口径.md) 定义“事实是什么”；本文只记录当前工具“如何存、如何读”。若字段命名与业务语义产生冲突，应修接口或增加映射，不能反改业务定义。

## 2. 当前数据组

| 数据组 | SQLite 表 | 说明 |
| --- | --- | --- |
| 策略运行 | `strategy_runs` | 策略、数据日、交易日、创建时间和完成状态 |
| 策略排名 | `cb_rankings`、`stock_rankings` | 某次运行的候选顺序与展示字段 |
| 订单草案 | `cb_orders`、`stock_orders` | 某次运行的买卖方向、数量和估算金额 |
| 账户事实 | `account_value_snapshots` | 分账户日期、总资产、账户现金和冻结现金 |
| 账户上下文 | `account_contexts` | 组合观察日和市场温度 |
| 持仓事实 | `position_snapshots`、`position_snapshot_items` | 可区分“没有快照”和“明确空仓”的版本化持仓 |
| 原始快照 | `raw_snapshots` | 策略运行需要复核的序列化原始或中间数据 |
| 市场温度 | `market_temperatures`、`market_temperature_refresh_state` | 来源时间、抓取时间和刷新失败状态 |

`account_snapshots`、`cb_positions`、`stock_positions` 是旧结构兼容来源，不应作为新功能的首选写入模型。

## 3. 当前账户标识

工程中当前使用 `stock`、`cb`、`changqian`、`cash`、`overseas` 表示五个承载通道。它们是账户标识，不等于策略定义。

- `stock` 当前承载小市值股票策略。
- `cb` 当前承载多因子可转债策略。
- `changqian` 当前承载国内长钱投顾组合。
- `cash` 当前承载现金池。
- `overseas` 当前承载海外长钱投顾组合。

公开投资模型接口单独返回资产类别、策略、账户和承载关系，避免通过余额字段猜测概念关系。

## 4. HTTP API

### 4.1 账户

| 方法与路径 | 当前用途 |
| --- | --- |
| `GET /api/account/latest` | 最新账户聚合视图 |
| `GET /api/account/summary` | 最新账户聚合视图 |
| `GET /api/account/history` | 账户快照历史 |
| `GET /api/account/model` | 账户、策略、资产类别及承载关系 |
| `POST /api/account/context` | 写入日期与市场温度上下文 |
| `POST /api/account/{account_id}/snapshot` | 写入单账户价值快照 |
| `POST /api/account/{account_id}/state` | 原子写入股票或转债账户价值与持仓 |

账户现金可由“可用现金 + 冻结现金”得到；冻结现金计入总资产，但不应成为订单可用资金。

### 4.2 持仓

| 方法与路径 | 当前用途 |
| --- | --- |
| `GET /api/positions/{strategy}/dates` | 可用持仓日期 |
| `GET /api/positions/{strategy}` | 最新、指定日或截至某日的持仓明细 |
| `GET /api/positions/{strategy}/snapshot` | 带版本元数据的持仓快照 |
| `POST /api/positions/{strategy}` | 追加股票或转债持仓快照 |
| `GET /api/positions/{strategy}/quotes` | 持仓批量报价与估值 |
| `GET /api/positions/{strategy}/quote` | 单个证券报价与名称补全 |

当前 `strategy` 路径值为 `stock` 或 `cb`。这是接口历史命名，不应据此把账户和策略视为同义。

### 4.3 榜单与计划

| 方法与路径 | 当前用途 |
| --- | --- |
| `GET /api/rankings/{strategy}/dates` | 排名可用数据日 |
| `GET /api/rankings/{strategy}/latest` | 最新完整排名 |
| `GET /api/rankings/{strategy}/{data_date}` | 指定数据日排名 |
| `GET /api/rankings/{strategy}/{data_date}/export` | Markdown 导出 |
| `POST /api/rankings/{strategy}/run` | 触发对应策略运行 |
| `GET /api/plan/context` | 当前计划日与市场温度 |
| `GET /api/plan/transfer` | 当前资金调拨目标与步骤 |
| `GET /api/plan` | 汇总调拨、榜单、订单和输入检查 |
| `POST /api/plan/{strategy}/size-orders` | 按计划现金计算订单数量并入库 |

## 5. 日期与事实优先级

- 策略排名绑定数据基准日和适用交易日。
- 账户与持仓是事实快照，可在计划允许的输入窗口内更新。
- 计划日来自已保存或重新取得的市场温度来源时间。
- 缺失快照不等于零；明确空持仓需要保存空快照。
- 券商与平台真实事实高于本地报价估值和订单草案。

## 6. 尚未承载的正式口径

当前数据库尚未完整承载全体系外部现金流、生活分红台阶、累计盈利历史高点、基准净值、资金加权收益率和时间加权收益率。相关业务定义已经写入 [投资记录与绩效口径](../体系/投资记录与绩效口径.md)，后续实现不能通过现有表结构反推或删减这些要求。
