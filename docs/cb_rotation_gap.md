# CB-MF-Rotation v1 策略 Gap 说明

本文档用于对齐「原始既定策略」和「当前工程实现」之间的差异。是否接受这些差异，应由策略 owner 明确确认。

## 当前结论

当前版本已进入严格口径 MVP：核心排序框架已经落地，关键字段缺失、覆盖不完整或行情过期时会停止输出，不再静默跳过过滤条件。它仍不是生产版，主要剩余 gap 是暂停交易过滤、行业集中限制、稳定数据快照和回测。

## 尚未完全对齐项

| Gap | 当前状态 | 影响 | 建议 |
| --- | --- | --- | --- |
| 日成交额数据源 | 已恢复硬过滤；当前使用新浪批量行情和 AKShare 转债日线补齐，缺失或过期时停止输出 | 新浪日线逐只抓取存在限流风险 | 后续增加批量快照源，并保存每周收盘快照 |
| 正股总市值稳定性 | 已改为严格总市值口径，优先走 AKShare A 股全市场快照 | 东方财富底层接口不可用且无合格缓存时会停止输出 | 后续增加第二供应方和每周快照 |
| 强赎数据覆盖 | 依赖 `bond_cb_redeem_jsl` 补充；接口失败时可使用缓存 | 极端情况下强赎过滤可能滞后 | 保存快照并设置缓存最大有效期 |

| 暂停交易过滤 | 尚未单独实现 | 可能纳入停牌或异常交易标的 | 后续从实时行情或交易状态字段补充 |
| 行业集中限制 | 尚未实现 | 可能行业集中 | 后续补行业数据后实现单行业上限 |
| 极端市场保护 | 尚未实现 120 日均线风控 | 无系统性降仓 | 后续增强，不影响 MVP |
| 回测 | 尚未实现 | 无历史绩效验证 | 下一阶段建设周频回测 |

## 当前是否建议接受

可以接受为严格口径 MVP，但不建议直接作为无人值守实盘自动交易版本。

当前适合用途：

- 每周生成候选池
- 辅助人工复核
- 观察策略稳定性
- 沉淀数据和调仓记录

当前不适合用途：

- 无人值守实盘自动交易
- 大资金严格按模型下单
- 对流动性过滤要求极高的执行场景

## 数据稳定性优先级

后续迭代顺序建议：

1. 保存每周收盘后的关键字段快照，并记录数据基准日。
2. 给转债成交额和正股总市值增加独立的第二供应方。
3. 增加暂停交易过滤。
4. 增加行业集中限制。
5. 增加更多字段回归测试，防止数据源字段变化时静默跑错。
