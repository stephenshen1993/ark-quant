# CB-MF-Rotation v1 策略 Gap 说明

本文档用于对齐「原始既定策略」和「当前工程实现」之间的差异。是否接受这些差异，应由策略 owner 明确确认。

## 当前结论

当前版本是一个可运行 MVP，但还不是严格生产版。核心排序框架已经落地，数据稳定性优先级正在提高；最大 gap 是「成交额过滤」在当前稳定数据源下可能无法严格执行。

## 已对齐项

| 策略项 | 原始要求 | 当前实现 |
| --- | --- | --- |
| 数据源 | 优先 AKShare | 已使用 AKShare |
| 全市场可转债 | 获取全市场可转债 | 使用 `bond_zh_cov`，当前可获取全市场 |
| 正股数据 | 获取对应正股数据 | 使用正股历史行情计算动量、波动、市值估算 |
| 双低因子 | 转债价格 + 转股溢价率 | 已实现 |
| 正股 20 日动量 | 20 日涨跌幅 | 已实现 |
| 20 日波动率 | 正股 20 日历史波动率 | 已实现 |
| 小市值因子 | 正股总市值越小越好 | 已实现工程近似口径 |
| 价格过滤 | 转债价格 < 130 | 已实现 |
| 剩余规模过滤 | 剩余规模 > 3 亿 | 已实现，优先用强赎表补充 |
| 强赎风险 | 排除强赎风险债 | 已实现，使用集思录强赎表补充 |

| 调仓建议 | 根据当前持仓生成 | 已实现 |
| 输出目录 | `outputs/` 与 `logs/` | 已实现 |

## 尚未完全对齐项

| Gap | 当前状态 | 影响 | 建议 |
| --- | --- | --- | --- |
| 日成交额过滤 | `bond_zh_cov` 不提供稳定成交额字段，当前在字段缺失时跳过该过滤 | 可能纳入流动性不足标的 | 后续接入更稳定的可转债实时行情源；未拿到成交额时在报告中明确提示 |
| 正股总市值口径 | 当前用历史行情中的 `outstanding_share * close` 估算，更接近流通市值口径 | 小市值因子与原始「总市值」不完全一致 | 后续固定总市值数据源，并区分总市值/流通市值 |
| 强赎数据覆盖 | 依赖 `bond_cb_redeem_jsl` 补充；接口失败时可使用缓存 | 极端情况下强赎过滤可能滞后 | 保存快照并设置缓存最大有效期 |
| 暂停交易过滤 | 尚未单独实现 | 可能纳入停牌或异常交易标的 | 后续从实时行情或交易状态字段补充 |
| 行业集中限制 | 尚未实现 | 可能行业集中 | 后续补行业数据后实现单行业上限 |
| 极端市场保护 | 尚未实现 120 日均线风控 | 无系统性降仓 | 后续增强，不影响 MVP |
| 回测 | 尚未实现 | 无历史绩效验证 | 下一阶段建设周频回测 |

## 当前是否建议接受

可以接受为 MVP，但不建议直接作为无人工复核的实盘自动交易版本。

当前适合用途：

- 每周生成候选池
- 辅助人工复核
- 观察策略稳定性
- 沉淀数据和调仓记录

当前不适合用途：

- 无人值守实盘自动交易
- 大资金严格按模型下单
- 对流动性过滤要求极高的执行场景

## 数据稳定性优先级

后续迭代顺序建议：

1. 给关键数据源增加本地缓存和失败回退。
2. 每次运行报告必须写明哪些过滤条件被严格执行、哪些被跳过。
3. 固定可转债成交额数据源，恢复日成交额 > 3000 万的硬过滤。
4. 固定正股总市值数据源。
5. 增加字段校验测试，防止 AKShare 字段变化时静默跑错。
