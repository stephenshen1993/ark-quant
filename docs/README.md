# ark-quant 文档地图

> 状态：正式导航真源
> 职责：规定全仓库 Markdown 的职责、真源顺序、阅读路径和维护规则。
> 真源范围：文档应该放在哪里，以及发生冲突时以谁为准。
> 不负责：替代各专题文档中的具体规则或实现说明。
> 最后核对：2026-07-18

## 1. 真源顺序

```text
投资体系战略
  -> 体系级战术与记录口径
    -> 账户内策略规则
      -> 工程实现与使用说明
        -> 研究、复盘、历史档案和运行生成物
```

上层定义下层需要表达什么，下层只能说明如何实现或观察。代码、配置、API、页面和 `outputs/` 无权反向修改投资规则；发现冲突时，写入实现差距并调整工具。

## 2. 推荐阅读顺序

1. [投资体系总纲](体系/投资体系总纲.md)：长期战略和不可轻易改变的原则。
2. [仓位与再平衡规则](体系/仓位与再平衡规则.md)：当前正在盘点的资金调拨战术和待决问题。
3. [交易执行规则](体系/交易执行规则.md)：平台无关的计划生成与执行约束。
4. [投资记录与绩效口径](体系/投资记录与绩效口径.md)：事实、资金流与收益比较语义。
5. [小市值股票策略](策略/小市值股票策略规则.md)、[小市值股票策略验证记录](策略/小市值股票策略验证记录.md)、[多因子可转债策略](策略/多因子可转债策略规则.md)与[多因子可转债策略验证记录](策略/多因子可转债策略验证记录.md)：账户内策略规则及其非规范性证据。
6. [系统定位与边界](工程/系统定位与边界.md)和[当前实现状态](工程/当前实现状态.md)：ark-quant 如何辅助落实，以及尚未实现什么。
7. [日常运行手册](使用/日常运行手册.md)：使用当前工具执行一次完整流程。

## 3. 目录职责

| 目录 | 职责 | 是否可作为当前规则真源 |
| --- | --- | --- |
| `体系/` | 战略、体系级战术、执行和记录口径 | 是，按文档状态区分正式或盘点中 |
| `策略/` | 账户内策略的选取、持有、退出和调仓规则 | 是 |
| `使用/` | 当前工具的启动、页面和日常操作 | 否 |
| `工程/` | 系统边界、架构、接口、实现状态和工程决策 | 否 |
| `研究/` | 外部资料、数据源和策略证据 | 否，只提供输入 |
| `复盘/` | 按时间记录组合状态、执行和归因 | 否，只记录事实与观察 |
| `档案/` | 形成期、旧版文档、外部评价和历史材料 | 否 |

仓库根目录只保留 `README.md`、`AGENTS.md` 和工具适配入口等少量说明。生成报告放在 `outputs/`，不混入正式文档。

## 4. 冲突处理

- 战略与战术冲突：以总纲为约束，继续讨论战术，不擅自改战略。
- 体系规则与代码冲突：记为实现偏差，不能用代码覆盖规则。
- 使用说明与代码冲突：先核对当前行为，再修使用说明或实现。
- 研究结论与正式规则冲突：研究只能触发复盘，不能自动升级成规则。
- 历史材料与当前文档冲突：历史材料只用于追溯。

## 5. 维护约定

正式文档开头应注明：`状态`、`职责`、`真源范围`、`不负责`、`最后核对日期`。

规则变化时只在对应真源修改一次，其他文档改为链接，不复制参数。重大变化需要保留原因、证据和生效日期；尚未达成共识的公式、比例、阈值和频率必须标记为“盘点中”或“待验证”。
